# 观数 · 评论分析工作台

前端目录包含 React 主工作台和一套保留兼容的原生工作台：`src/` 是 React 分析、模型标注与人工复核页面；`workbench/` 是独立人工复核入口，提供进度统计、状态筛选、原文定位和人工修正。React 页面通过 `/api/v1` 接口访问人工复核数据；需要独立启动时，仍可使用 `python -m data_analysis_agent.cli.workbench serve --db env:DATABASE_URL`（默认端口 8765），无须 Vite 构建。启动方式见[人工复核工作台说明](../docs/review-workbench.md)。页面资源已从后端包移到此处，后端只保留服务和接口。Python 安装包仍会携带这些资源，安装后无需保留源码目录。

后端现支持 SQLite / PostgreSQL，前端接口和配置保持一致。PostgreSQL 配置及旧数据迁移见 [数据库接入说明](../docs/postgresql.md)；后端启动示例中的 `--db data/private/reviews.sqlite3` 可改为 `--db env:DATABASE_URL`。数据库凭据只配置在后端。

独立的 React + TypeScript + Vite + Ant Design + ECharts 前端，接入现有 `/api/v1` 评论服务，界面为简体中文。无需修改 Python 业务代码。

HTTP 服务支持结构化评论统计和[只读评论 Agent](../docs/review-agent.md)。首页选择数据集、商品和分析时间；“开始分析”执行固定统计，“Agent 问答”调用模型选择趋势、对比和证据工具。对比时间、标注版本和可选备注收在“高级设置”；备注仍只标识结构化分析。浏览器先上传所选文件再创建导入任务；下载是后端真实 JSON 的浏览器导出。

导入进度分为“文件上传”和“数据处理”：上传条按浏览器实际发送的字节数计算，两份文件合并显示，发送完后等待服务器确认；处理条显示后端当前校验或读取步骤的真实字节进度，并列出实际处理行数、新增和无效条数。切换步骤时百分比会重置，读取 100% 后仍需完成校验和入库。gzip 读取量包含解压缓冲；达到新增上限也可提前结束读取。事务提交成功后才显示处理完成，坏行则显示部分完成。上传时保持页面打开；任务提交后刷新可以恢复处理进度。

## 启动

根目录 `LABEL_EXECUTION_MODE=redis` 时，**00 一键启动前后端** 会同时启动 Redis 标注 Worker；手动启动 API 时需要另开终端启动 `queue worker`。使用 IDEA 时，选择 **00 一键启动前后端**，或右键根目录 `run.py` 运行。服务就绪后自动打开页面，日志显示在同一个“运行”标签中，停止时一起关闭前后端。单独启动前端可选 **80 启动前端工作台**。统一入口需要 PATH 中存在 Node.js；配置说明见 [IDEA 运行说明](../docs/idea-running.md)。以下为终端分别启动的方式。

需要 Node.js 22.12+，以及已安装项目依赖、已显式初始化的后端数据库。后端安装与初始化见 [HTTP API 说明](../docs/review-http-api.md)。不要用验收脚本初始化业务库。

从项目根目录启动后端（现有业务库已经初始化时）：

```powershell
.\.venv\Scripts\python.exe -m data_analysis_agent.cli.server serve --db data/private/reviews.sqlite3 --port 8000 --import-root data/private --env-file .env --allow-origin http://127.0.0.1:5173
```

另开终端启动前端：

```powershell
cd frontend
npm ci
Copy-Item .env.example .env.local
npm run dev
```

打开 `http://127.0.0.1:5173`。已有 `.env.local` 时直接编辑，勿覆盖自己的配置。前端不需要 Python，也可以将 `frontend/` 作为独立项目安装和构建。

## 环境配置与构建

| 配置 | 作用 |
| --- | --- |
| `VITE_API_BASE_URL` | API 基址，含 `/api/v1`。示例 `http://127.0.0.1:8000/api/v1`；未配置时为同源 `/api/v1`，需由部署环境反向代理 |
| 后端 `--allow-origin` | 必须与浏览器实际前端 Origin 完全一致；`localhost` 和 `127.0.0.1` 不同，可重复传参 |

`VITE_*` 会进入浏览器代码，只放公开 API 地址。模型密钥继续留在后端 `.env`；前端仅使用 `/options` 返回的模型身份选择既有标注版本。

```powershell
cd frontend
npm run build
npm run preview
```

构建产物在 `frontend/dist/`，可独立托管。预览端口是 4173，后端需额外设置 `--allow-origin http://127.0.0.1:4173`。Vite 环境变量在构建时注入，改地址后需重新构建。后端仍限制本机 Host，因此此版本面向本机工作台，公网部署还需要后端提供相应访问能力。

## 完成一次分析

导入后可直接在页面完成模型标注：

1. 导入成功后会显示新增、重复数量，点击“标注已导入的数据”继续；也可通过顶部“准备数据”打开表单。导入完成后的入口自动带入数据集，首页入口沿用当前数据集和商品。
2. 确认商品（留空表示该数据集全部商品）和本批数量。每批可设 1–1000，默认 100，是所有商品合计上限，不会自动循环。“处理设置”中可调整并发数（1–4，默认 2）或勾选重试失败评论。
3. 点击“开始准备数据”。使用后端 `.env` 配置的模型，不受分析日期窗口限制；范围可能包含以前导入的未标注评论，同一版本下的成功记录会跳过。
4. 页面自动显示已处理/实际选中总量、成功、失败、模型调用数，刷新可恢复。完成后显示将使用的分析、对比时间，点击“分析这些评论”直接提交分析，沿用本次商品和标注版本；“调整分析范围”返回首页修改范围；“继续标注下一批”保留商品、批量和并发设置。
5. 导入、标注的原始 JSON 默认收在“处理明细”，按需展开或下载。

模型密钥仍由后端管理；配置缺失、请求失败或执行器离线会显示提示。分析与标注是各自独立的任务。

1. 在“分析工作台”选择数据集、商品和分析时间。空商品选择表示该数据集全部商品；不同来源和版本不会混在一起。初次日期参考评论库最新月份，对比期自动取分析开始月份的上一个月；之后沿用已选时间。
2. 如需自定义对比时间、切换已有标注版本或填写备注，展开“高级设置”。自定义对比期不会随分析时间变化，可点击“恢复自动对比上一个月”。执行内容固定为评论趋势、商品对比、六维度负面问题及基线规则分析。
3. 点击“开始分析”。任务以幂等键提交，轮询后端状态；未知总量只显示阶段，执行器离线会明确提示。
4. 阅读实际统计结论、趋势图、表格和冻结原文证据。数据不足、未标注和空分母分别显示，不会把空分母当成 0%。
5. 点击“下载 JSON”导出完整分析快照和本机备注；右侧详情也可单独导出。

顶部“导入数据”是工作台唯一的导入入口。评论文件支持 CSV 和 Amazon JSONL / JSONL.gz；商品元数据支持 Amazon JSONL / JSONL.gz，也可仅导入元数据。CSV 支持 UTF-8（含 BOM）和 GB18030，需包含商品ID、评论内容、评论时间，兼容 `product_id`、`text`、`review_time` 等英文列名；可包含打分、用户ID、商品名称和品牌。CSV 使用独立的 `reviews_csv` 来源，默认版本为 `reviews-csv`，不能同时添加 Amazon 元数据。交易、用户行为、数据库或 ZIP 文件不能用于此评论导入入口。

支持从电脑任意位置选择文件、中文文件名和空格路径。单个文件最大 512 MiB，空文件或不支持的格式会直接提示。上传与提交任务分别显示加载状态，提交失败保留已选文件和已上传路径，再次提交沿用幂等键。

上传副本保存在 `import-root/.uploads/`，供后台任务、失败重试和原文追溯使用，不需要手工把源文件复制进项目。副本目前随服务保留，删除任务记录或导入数据不会自动清理磁盘副本。Amazon 评论时间戳限定为 1996—2023 年、单位为毫秒；CSV 时间支持 ISO 日期时间及 `YYYY/M/D HH:mm[:ss]`，有时区的时间转换为 UTC，无时区的时间按 UTC 解释。

“本次最多新增评论数”可填写正整数（例如 1000），留空不限。重复记录不占额度；达到数量后停止解析评论，后续记录不在本次检查范围内，商品元数据仍按原规则完整处理。再次提交会跳过已有评论继续新增，已有全部评论时不会重复增加数据。仅导入元数据时请留空此项；后端文件指纹校验仍会读取完整文件。

页面使用固定 Header、左侧工作空间导航与右侧独立滚动的主内容区。“数据管理”只展示数据目录、导入和原文查看；模型标注表单、处理设置、批次进度与后续操作统一属于独立的“评论标注”模块，人工复核入口也位于该模块。“任务与报告”是主内容区独立页面，支持刷新、分页、状态查看和结果恢复；分页位于列表底部，删除任务使用页面内确认。长标题可换行，当前查看的任务单独标记。手机端通过工作空间导航切换相同功能。数据集、商品、时间、自定义对比期、标注版本和备注按 API 地址保存在浏览器 localStorage，刷新及流程切换后继续沿用，不同步到其他设备。清理浏览器存储会丢失这些选择和备注，但后端任务与分析快照仍在。

前端采用现有 History API，不增加路由依赖。导航高亮由当前 URL 所属模块决定，支持刷新和浏览器前进、后退：

| URL | 页面 |
| --- | --- |
| `/analysis/new` | 评论分析；旧 `?mode=agent` 自动进入 AI 助手聊天页 |
| `/assistant` | AI 评论分析助手：消息独立滚动，底部输入区固定 |
| `/assistant/tasks/:taskId` | 在聊天页只读恢复已有 Agent 任务 |
| `/data-management` | 数据管理 |
| `/annotation` | 评论标注表单；`/annotation/prepare` 兼容跳转到此处 |
| `/annotation/tasks/:taskId` | 标注任务进度和结果；继续下一批仍在评论标注模块 |
| `/tasks` | 任务与报告 |
| `/tasks/:taskId` | 既有任务详情；标注任务和 Agent 问答按实际类型归入各自模块 |

旧 `/` 入口继续读取本机选中任务作为兼容恢复；显式 URL 优先。标注准备范围及提交过的批次参数保存在当前浏览器历史条目中，返回或刷新时恢复；访问任务 URL 只读取既有任务，不重新提交模型工作。独立静态托管需将上述前端路径回退到 `index.html`；Vite 开发和预览服务已提供该回退。

AI 助手使用既有 `analysis` 任务和当前商品、日期、标注版本参数，每次提问仍是独立查询，不把本地对话作为多轮记忆发送。聊天仅在按 API 地址区分的 localStorage 中保存问题、范围与任务引用；答案和统计在刷新后从真实任务结果恢复，不保存另一份结果副本。提交失败可用原幂等键重试，后端失败任务沿用原 retry 接口。Enter 发送、Shift+Enter 换行；原文详情、工具执行与 JSON 导出保留在消息内。常用 Markdown（强调、标题、列表、引用、链接、表格、代码）通过 React 文本节点呈现，原始 HTML 不执行，不增加渲染依赖。

## 接口与前端功能

| 接口（均位于 `/api/v1`） | 前端用途 |
| --- | --- |
| `GET /health` | 服务及 worker 心跳状态 |
| `GET /options`、`GET /quality` | 数据集/商品/模型版本选择、评论范围与数量；来源和版本组成前端数据集分组 |
| `GET /reviews`、`GET /reviews/{id}` | 当前数据预览、原文与字段详情；历史证据使用已保存的 run.inputs |
| `POST /import-files` | 上传浏览器选择的评论或元数据 JSONL / GZ 文件，返回副本的任务路径 |
| `POST /tasks` | 提交 `analysis`、`import` 或 `label` 及其契约参数，带 `Idempotency-Key` |
| `GET /tasks`、`GET /tasks/{id}` | 历史分页、真实状态/阶段、结果引用和错误 |
| `POST /tasks/{id}/retry` | 仅 failed/partial 可重试，产生关联的新任务 |
| `DELETE /tasks/{id}/imported-data` | 删除指定导入任务产生的评论、错误记录和关联标注；共享商品信息保留 |
| `DELETE /tasks/{id}` | 删除任务记录及其重试子链，不删除业务数据；运行中的任务不可删除 |
| `GET /analysis-runs/{id}` | 冻结范围、统计、趋势、对比、问题、证据，所有结果卡片的唯一数据来源 |

`analysis.parameters` 提交 `model/base_url/prompt_version/source/dataset_version/product_ids/date_from/date_to/baseline_from/baseline_to`。基线结束必须早于当前窗口开始。规则使用后端默认值；分析可能保存规则告警，并不调用模型。`import.parameters` 为 `reviews_path/meta_path/dataset_version/product_ids/max_reviews`，至少一个文件路径；`max_reviews` 可选，要求评论路径且为正整数。

`label.parameters` 提交 `source/dataset_version/product_ids/limit/workers/retry_failed`。模型身份由后端冻结，前端不提交密钥或模型配置。

成功包络为 `{status:"ok", result: ...}`。错误为 `{status:"error", error:{code,message,details?}}`，界面显示业务及字段错误；统一 API 层处理 JSON、HTTP、超时和网络异常。请求超时 30 秒。任务每 1.5 秒串行轮询，网络失败后每 5 秒重连，保持最后已知状态；终态停止轮询。切换任务或退出页面会中止请求及计时器。

当前无用户账号或 Token；沿用后端本机 Host 和 Origin 校验，不新建浏览器认证方案。

## 后端边界

- 已支持单轮只读 Agent 问答，使用已有范围与标注，结果随任务保存；无多轮会话 CRUD。结构化分析备注仍保存在本机。
- 浏览器支持 JSONL / JSONL.gz 评论及商品信息文件上传；其他文件格式尚未接入评论导入。
- 无取消任务；没有取消按钮。失败/部分完成才显示显式重试。
- 无生成文件清单或下载接口；JSON 为浏览器导出，图表由后端统计数据渲染。
- CSV/Excel 销售分析仅有 CLI；当前工作台仅接评论 HTTP API。
- 前端分析需要已有标注版本；无版本时可使用页面内“准备数据”入口。人工复核页面位于 `/annotation/review`，模型连接配置和告警管理仍未提供。

主要文件：`src/api.ts` 统一请求；`src/useTask.ts` 与 `src/task-state.ts` 管理轮询；`src/Composer.tsx` 管理分析输入；`src/ResultCards.tsx` 展示快照；`src/features/datasets/components/DataPreviewDrawer.tsx` 提供数据详情入口，内部由 `DatasetPreview.tsx` 展示当前原文；根目录 `src/DataPreview.tsx` 仅保留兼容导出；`src/App.tsx` 组合工作台。
