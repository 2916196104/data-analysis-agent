## 二、实际代码边界

以下是静态代码事实及其含义：

- [review_intent.py](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_intent.py:346) 的 `_resolve_review_request` 先调用 `wants_semantic_search`；未进入语义检索分支不等于一定走错工具，后续规划或澄清仍取决于输入及上下文。`_followup_intent` 只对特定历史和短追问提供澄清，不能证明任意多对象长问句的路由。
- [review_retrieval.py](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_retrieval.py:31) 使用有限关键词检测语义检索，`retrieval_request` 保留原问题并生成最多 5 条候选请求；该请求并非能直接绑定这批历史固定池。
- [review_task_contract.py](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_task_contract.py:18) 的 `evidence_question` 只在安全条件下分离日期/SKU；[build_task_contract](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_task_contract.py:127) 根据已生成计划和 `target()` 编译事实。`RequiredFacts` 可表示 all/any 和同评论、前后关系，但结构可表示不代表自然语言解析器、事实判断或输出模板已支持这些关系；未解析的复合请求可受控标记 unsupported。
- [review_reported_facts.py](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_reported_facts.py:54) 的 `target()` 使用有限完整问句与事实词表；`assess()` 再次从字符串解析目标，逐观点检查明确事实和上下文，并按 review_id 合并同评论事实。它不是接受任意结构化事实契约的 API，也不是通用语义蕴含或反例分类器。`OPPOSITES` 用于上下文冲突否决，不等同向用户发布受限反证。

## 五、元评审形式与真实业务缺口

**A：接口形式不匹配。** RB08、RB09、RB10、RB15 直接询问“这些候选能否证明”，并携带固定候选池或反证评审前提；生产接口主要面向查询评论，而非接受人工构造的证据评审任务。增加这些原句的专用硬编码并不能证明生产能力。RB03 也包含保存池与引用的额外元数据，需先明确保存池是否为生产支持的范围。

**B：与实际用户相关的能力缺口。** 未收货与签收的同评论关系、联系与自动回复关系、配送与安装的对象隔离、效果与速度的非蕴含、限定反例与歧义澄清，均可出现在自然业务问题中。现有部分机制对这些问题有安全限制，但缺词表、完整关系解析或可解释结果，不能全部归因于 A 类措辞，也不能在未经运行时验证时认定已发生错误发布。

## 六、两种可比方案——均为设计，未实施

### 方案 A：保留原题完整语义

保留原问题、固定池范围、对象、必要关系、否定、引用和澄清要求，直接作为生产输入。当前八题状态见第三节：没有一题可静态标为完整 SUPPORTED；不得删除前缀、把“这些保存评论”偷偷换成实时 Top-K、把复合问题拆成单事实后声称原题通过。将来必须经独立协议确认输入上下文与接口目标匹配，逐步验证 Router、目标契约、来源、判断、Validator 和回答；不可表达的单元 N/A 并单独报告覆盖率。

### 方案 B：历史固定候选的盲态事实判断

建议将**输入包、预测和评分**物理隔离：

1. 从冻结原始问题及原始来源另行准备、独立审查的任务声明：原问题、经验证的商品/日期、固定池身份、欲判断事实与关系、时间/否定条件、允许使用的原始候选及其可追溯历史观点。这个声明只能根据问题和范围制定，不含人工标签、答案、`candidate_decisions`、人工许可与人工选择的支持区间；盲态数据清单先冻结并哈希。
2. 判断阶段只读取该盲态包。候选必须带完整历史身份及全文，并保留判断器可见的原始观点，不按 A/B/C/D/E/F 筛选或排序；不要把 24 个由人工选择的 Q 当作预测提示。原始固定候选不是本轮检索 Top-K，结果不能度量召回或当前源。
3. 现有 `assess(question, evidence)` **只能接收问题文本和候选**，它内部重新调用 `target`，不能直接接收上述结构化事实；不能把人工契约注入或把未解析条件当作成功。若独立确定有等价的受支持表达，只能作为另行标记的**子命题检查**，必须保留原题及全部未表达条件，不能称作原题自然语言理解通过。是否可等价仍需人工/契约审核。
4. 不伪造来源认证结果、生产 key、快照或调用成功。部分获批 Q 是从全文新截取的区间，并非现有历史观点键；它们不能未经认证冒充 `RagOpinionDocument` 或 `validate_retrieval` 接受的真实观点。只作判断器组件级检查时，不得声称生产 Validator 已通过；如未来做完整 Validator 检查，需真实满足其身份、快照、查询和权限契约，否则 N/A，不得绕过。
5. 冻结预测与执行日志后，评分器才读取 Gold Reference 对照事实、关系和用途。不能仅凭 `unknown` 自动推断反证，也不能把无证据自动判定为负事实；不改变人工答案。拒绝、无法解析、无法绑定来源和未执行分开计数。

此方案可先验证**现有支持子集**，不能通过适配器凭空实现缺失的结构化输入、完整原题、当前数据来源或业务能力。特别是 RB04 的新事实、RB16 的原题澄清，以及 RB09 的反证语义，缺少可证等价时必须 N/A。

## 八、不可比较与准入

- 将目标结构从 Gold 裁决答案抽取后输入判断器、以人工 Q 区间选取正样本、用当前模型输出反写标准：数据泄漏，**不可评分**。
- 原问题或必要关系无法解析、人工来源身份无法在被测路径内认证、固定候选不能安全装配、未经批准的上下文引用：相关单元 **N/A 或受控阻断**，同时报告可评分分母和覆盖率。
