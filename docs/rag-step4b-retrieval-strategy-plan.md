# RAG Step 4B 检索策略开发计划

日期：2026-11-04（Asia/Taipei）。状态：**仅规划，未实施**。

Step 4A 已冻结 24 条问题、48 组检索和 222 个返回条目的人工评分。14 条 answerable 问题上，预设过滤使 P@5 从 41.43%（29/70）提升至 52.86%（37/70），MRR@5 从 0.779762 提升至 0.880952（各 n=14）；10 条 no_known_relevant 问题的候选返回率从 10/10 降至 8/10。详见 [最终质量审查](rag-retrieval-quality-final-review.md)。这些数值支持继续做离线策略实验，尚不构成上线或 Agent 集成许可。

最优先的功能是**按所问主题、情感和事实条件判断证据是否足够，给出可回答、只能有限回答、应拒答的明确结果**。先做最小查询契约作为输入，再验证该判断；完整自动意图识别与过滤在其后单独评测。

## 2. 4B-1：查询意图与过滤条件

### 2.1 最小语义契约

拟新增独立的纯函数契约，不挂接现有 Agent。输出至少包含下列信息，所有枚举与合法范围复用项目现有定义。

| 字段 | 含义与约束 | 例子 |
|---|---|---|
| task_type | `statistics / evidence / mixed / clarify` | 比例/排名/趋势归统计；是否存在某种具体反馈归证据；同时询问时拆分 |
| aspect_candidates | 一个或多个候选维度及推断依据；不确定可为空 | 安装与配送应保留服务对象区别，不只依赖“迟迟”等关键词 |
| sentiment_intent | positive / negative / neutral / unknown / mixed；表示查询目标，不是见到否定词就判负向 | “客服并没有让人久等”目标是正向时效 |
| target_entity | 评论中的对象或角色，不是擅自识别/切换业务商品 | 客服、安装人员、物流人员、机器部件 |
| subtopic | 查询的具体问题，允许未知，避免新增过大分类体系 | 响应时效、安装等待、制冷、制热、噪声、配送承诺日期变更 |
| required_facts | 回答必须有的限定、关系及子问题 | 已到货 + 未安装；明确原承诺日期 + 后续变更 |
| polarity_structure | 否定作用对象、转折及同评论正负共现要求 | “不是制冷快，而是降不下温”是负向；mixed 需要同一评论中的关系证据 |
| proposed_filters | aspect/sentiment 的合法子集；不含未经验证的商品/日期范围替换 | mixed 不能直接传给现有 sentiment 过滤参数 |
| uncertainty / clarification | 明确歧义和待澄清项；模型自报 confidence 不能当校准概率 | 宽泛“总体不错但有缺点”不强制解释为 effectiveness |
| scope_ref | 引用执行前冻结的范围身份，只读继承 | 模型不得从历史或自然语言替换已验证商品和日期范围 |

当前 frozen filtered 是人工指定的诊断对照，并非自动路由结果，也不是语义完备的金标准。Q13 有 quality 标签下的噪声相关证据被 effectiveness 过滤排除；Q21 的宽泛混合查询也不一定应限定 effectiveness。因此自动条件“完全匹配 manifest”与“找到充分证据”必须分别评价。

### 2.2 候选方法与失效处理

先在合成开发样例上实现易审计的规则/结构化解析，必要时再比较独立模型提取方案，不在本阶段接入业务 Agent。规则与模型哪种更好由盲评决定，不预设结论；模型提取仅需自然语言问题，不需发送评论或人工答案。

明确单维度、单极性的查询可提出硬过滤；服务对象/维度模糊时保留候选维度或澄清。是否使用双路候选合并只作为后续单独实验，不静默放宽范围，也不把“过滤为空”直接解释为全数据没有相关评论。neutral 零覆盖、mixed 关系及产品主题不匹配，应显式记录原因。

统计问题继续交给现有确定性统计路径。受限 Top-K 只能说明找到哪些候选，不可回答完整数据的发生比例、总体排名、变化趋势或绝对不存在。mixed 任务先分别给统计与证据计划，不能用样本数冒充全量分母。

### 2.3 意图评价

逐字段报告有效样本数：task_type 路由正确数/适用查询数、aspect 与 sentiment 匹配数/适用数、子主题及 required_facts 人工认可数/可判断数，以及不确定/澄清覆盖。neutral、unknown、mixed 分开保留，不填 0 代替 N/A。

现有 24 题本质上以证据检索为主，不足以评价 statistics/mixed 路由。需另建包含统计、存在性、歧义、否定、跨对象和多子问题的开发/验证题，不能直接宣称统计路由已验证。现有 aspect/sentiment 可作 frozen 目标；新字段需人工另行标注，不能把系统输出当金标准。

## 3. 4B-2：证据充分性与拒答

### 3.1 独立判断器

输入为查询语义契约、带稳定来源键/字符区间/版本的候选、必要时已授权的原文上下文和索引覆盖说明。输出为 `sufficient / limited / insufficient`、支持的事实或子问题、可引用证据、未支持条件及结构化 reason。这是判断与证据选择模块，不先生成自由文本业务答案。

| 判断 | 需要满足的事实约束 | 允许表达的边界 |
|---|---|---|
| sufficient | 来源有效，主题、对象、极性与必要条件相符，证据直接支持所要陈述；存在性可由有效的直接实例支持 | 只确认受限范围内找到此类实例，不推出频率、普遍性或全部商品结论 |
| limited | 多子问题仅部分得到直接支持，或已有直接证据但时间、因果、代表性等扩展条件不完整 | 明确支持哪部分和缺哪部分；不得把部分相关当作核心问题已获支持 |
| insufficient | 空候选、仅主题相似、对象/极性相反、关键条件全部缺失、证据失效、所问功能无支持 | 对核心问题拒答或请求澄清；不能用“没有这种反馈”替代“当前证据不足” |

同一评论正负共现须在同一 review 的上下文中核验；不能拼接两条不同评论合成 mixed。处理相互冲突证据时保留来源和限制，不自动多数投票为确定事实。重复观点或同评论多个切片只算一个来源，不用重复次数制造证据丰富的印象。

运行时判断器不得读取本次 human grade。离线测试可用冻结 0/1/2 标签判断候选支持程度：Top-K 全部 0 分时，核心问题必须 insufficient；仅有 1 分时不得承诺核心结论；有 2 分也不能自动支持超出其内容的睡眠影响、长期耐用性或总体比例。新状态的参考答案需要人工确认，不能直接把“有 2 分”机械等同于完整充分性。

### 3.2 相似度与上下文

cosine distance 只作为排序/诊断特征；不等同于相关性、置信度或充分性，不使用未经验证的固定阈值。Q07 更近的泛化配送候选仅部分相关，Q11 更近的候选极性错误，已经说明单靠近邻排序不能证明事实成立。

若未来比较阈值或校准模型，应在独立开发数据上按查询类型拟合，记录样本量、代价、校准曲线和选择过程，锁定后在未使用的验证数据上检验；14 条已见问题不足以确定生产阈值。优先比较可解释的对象、主题、极性和条件支持校验，不先用距离截断掩盖错误。

最小上下文实验只回看 review.json 中已有候选对应的保存原文，不更改 quote-utf8-v1 或真实向量。记录“原片段缺条件 / 原文可补足 / 原文也缺事实 / 原文冲突”的人工分类。扩大到其他已索引评论的原文或调用外部模型，先单独界定数据授权；未索引 891 条不纳入本计划默认实验。

## 4. 4B-3：最小可执行对照实验

### 4.1 先冻结评价协议

实施前登记候选配置、提示词/规则版本、代码提交、依赖版本、输入哈希、允许范围、指标及停止规则。保留原基线 run_id 和 labels SHA-256；所有新实验写新目录，不覆盖 archive 或 baseline-v1。一次比较一个主要变量，避免同时改变过滤、候选数、排序和判断器而无法归因。

以下是最小顺序，不要求一次完成全部实验；每一项结束后人工审阅再决定下一项。

| 实验 | 对照与候选 | 固定条件 | 能回答什么 / 不能回答什么 |
|---|---|---|---|
| E0 基线回放 | 原 U 与人工预设 F；不改变排名 | 冻结 24 题、222 条候选、原分数与指标 | 验证评价实现和归档，不宣称有新增质量改善 |
| E1 证据充分性，最高优先 | 同一 U/F 列表上，对照“非空就允许回答”的离线风险规则与候选判断器 | 先用人工查询契约隔离自动解析误差；不把人工相关性分数输入候选判断器 | 看是否减少无支持的允许回答，同时报告可回答题被拒风险；这不是已有 Agent 的线上对照 |
| E2 自动意图与过滤 | 自动推断条件对比 U 和原人工 F，单独报告意图误差 | 相同 200 条、BGE-M3、scope、Top-5、原始排序与相同判断器 | 测自动条件造成的变化；原 F 仅作诊断参照，非全部语义证据的上界保证 |
| E3 单一排序优化，择一 | E1/E2 较稳方案上增加“细分主题/条件校验重排”，先限于已保存候选并集 | 候选来源、scope 和向量不变；基线始终展示 | 只能评价重排已召回证据；不能宣称修复未召回证据或提高全语料 Recall |
| E4 上下文消融，可选后续 | 同一候选判断分别仅看 quote 与增加其已保存原文 | 排名、候选集合、同一判断器协议固定；原文仅作验证上下文，不改 embedding 输入 | 区分上下文缺失与真实事实缺失；须人工重新判断条件支持，不能承诺必然改善 |

E1 第一轮可直接离线回放原 48 个列表，不连接 DB、不运行模型编码。E2 若出现基线未展示的新候选，必须补充人工评分；E3 首轮限于每题原 U/F Top-5 的去重并集，最多 10 条，逐项检查该 query/key 的既有标签覆盖。E4 的充分性标签需要新增人工核验，即使原相关性标签可复用也不能自动升级。

Top-10 扩候选、双路合并、词法/混合检索或额外重排模型均是后续备选，不列为首轮必做；若选择，另立一次实验，保持原 200 条索引，并为新 query/opinion 对盲标。任何需要重建向量、换模型、改 builder 或扩覆盖的方案都另立阶段、另行授权。

### 4.2 人工标注、测试与泄漏边界

现有冻结 24 题及标签已被审阅用于本计划，属于**公开于开发者的诊断/回归基准**。仍必须用它比较可复现差值，但不能反复在它上面调参，再称独立测试或泛化有效，也不能事后重写问题、criterion 或标签提分。

最小数据安排如下：

1. 开发：先用合成查询和合成证据覆盖路由、否定、角色、前提、全 0 分、失效引用及重复来源；不冒充真实质量样本。
2. 固定回归：原 24 题一次登记配置后执行；保留所有不利结果。每项配置及反复试验次数记账，选择后的结果只称这份基准上的结果。
3. 泛化验证：若要宣称能进入更广业务使用，另由人工独立写一批未用于规则/提示词选择的问题，实施前确认数量与分层配额并封存。先固定全部方案再揭示标签。保持同一 200 条范围，明确这也只验证新问法/新主题在该受限语料上的表现，不证明跨商品或全量泛化。

新候选的 query/key、原文版本与评判标准相同且已有合法标签时，可以复用冻结评分，并记录来源；无标签时保持 unjudged，提交人工盲审，不能当 0 或从余弦值推断。盲审界面隐藏候选方案名和距离，先去除同 query/key 重复项，再按统一规则评分；有分歧由人工裁决，新增标签独立存放，绝不回写旧 baseline。

no_known_relevant 的冻结状态不是全 200 候选的完备否定。新方案若找到并经人工确认了直接证据，记录新实验的证据状态与变化原因；不能将它继续视为假阳性，也不能倒改原分数后横比。主报告分别给原适用分母的配对结果和经新评审的补充结果，明确两者不可混用。

### 4.3 指标和人工确认门槛

| 评价面 | 指标与分母 | 决策要求 |
|---|---|---|
| 候选相关性 | P@1/@3/@5、Partial@K、Hit@5、MRR@5，各自有效查询数；固定 K 分母；同 query 配对及 aspect/sentiment 分组 | 基线始终保留，报告提升/不变/下降题数；小分组不排名，不把 N/A 填 0 |
| 自动意图 | task_type、aspect、sentiment、对象、子主题与条件的人工匹配数 / 可判断数；歧义单列 | 手工 F 的结果不能替代自动条件验收；字段新增金标准需人工确认 |
| 判断器安全性 | 无支持却允许回答数 / 人工判无支持的有效列表数；Top-K 全不相关列表的拒答数 / 全不相关列表数 | 冻结 48 列表中 Q03/Q19/Q21/Q23 两模式共 8 个全 0 分列表应全部拒绝核心结论，这是候选功能要求，尚未实现 |
| 判断器可用性 | 有直接证据却完全拒答数 / 人工确认可支持的有效列表数；允许回答且证据支持数 / 允许回答列表数；limited 判定人工一致率 | 与安全性同时报告，防止全部拒答制造好看的风险指标；不先把“存在2分”视为充分性全部金标准 |
| 无已知证据 | 原 10 题候选返回率、0/1 分构成、判断器输出；按 query 与 query-mode 区分计数 | 原候选返回率不等于回答错误率；有新直接证据时单独复核适用状态 |
| 来源与边界 | 范围越界、失效来源、身份冲突、私有数据泄露、修改真实数据的事件数 | 任何一次均停止该方案评价，不能靠平均质量抵消 |
| Recall@K | 全候选 qrels 不全时 N/A，有效完整判断查询数 0 | 不用候选命中率或固定Top-K替代 |
| 成本与稳定性 | 每有效查询耗时、额外请求/上下文量、超时及失败率；仅实测后报告 | 不预填当前没有测过的吞吐、成本或生产 SLA |

业务门槛需人工确认，包括：最低可接受 P@K/MRR、允许的无支持回答与过度拒答比例、各关键类型的最低样本量、是否接受 limited 输出及其措辞。可把“原全 0 分列表全部拒绝、无范围/来源违规、不得把部分相关升级为直接支持”作为首批功能要求；**不能由本计划自动批准数值质量门槛或直接宣称已经达标**。

配对提升可报告均值、逐题变化及探索性不确定性区间；n=14 和小分组不足以支撑强泛化结论。独立验证集出现失败后应保留结果并回开发集修订，重新版本化验证协议，不继续盯着同一批封存题调参。

## 5. 拟议实现位置与交付顺序

复用点是现有 [retrieval_evaluation.py](../src/data_analysis_agent/reviews/retrieval_evaluation.py) 的冻结契约/评分和 [embedding_store.py](../src/data_analysis_agent/reviews/embedding_store.py) 的 `search_effective_opinions()`。后者已支持 aspect/sentiment 只读过滤、有效来源复核及精确距离排序，首轮不改它。现有 `agents/review_intent.py`、`review_evidence*.py` 仅作为将来集成时的职责参考，本阶段不修改或接线。

未来实施可采用少量独立纯函数文件承载查询契约和充分性判断，一个离线实验入口加合成专项测试；最终文件拆分在获准实施时按实际复杂度确定，不预建通用策略框架。

| 顺序 | 具体交付 | 完成后停止点 |
|---|---|---|
