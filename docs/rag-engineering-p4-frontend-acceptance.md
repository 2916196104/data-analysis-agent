# P4：前端 AI 助手真实使用验收

2026-11-06。**已从真实 React 页面提交并完成完整链路，达到当前单商品、已覆盖问法的最低可用标准。** 真实任务共 6 个：5 个正常成功（4 次语义、1 次 SQL），另 1 个刻意使用无效本地解释器配置验证失败处理。没有外部 LLM 调用；业务 PostgreSQL 只读，原模型、200 条向量、语义许可规则和来源校验保持不变。

## 实际链路与运行方式

`React AiAssistantPage → useAgentChat → POST /api/v1/tasks → 真实持久队列 → TaskWorker._execute → run_review_agent → search_semantic_evidence → 默认 SemanticRetrievalService 工厂 → 持久 BGE-M3 子进程 → pgvector → 独立来源/事实许可校验 → public_answer → useTask 轮询 → 原文展开`。

测试使用项目已有 Chrome/Playwright、React/Vite、FastAPI 和 **未替换的 TaskWorker/Agent/Encoder**。业务库是现有 PostgreSQL；为遵守只读边界，任务状态写入 Git 忽略目录内独立的真实 SQLite 队列，而未写入业务 PostgreSQL 任务表。不是 API mock 或 FakeRepository；页面提交、排队、执行、轮询和渲染均真实发生。生产 PostgreSQL 队列写入与正式部署代理未在本轮执行。

范围为 `reviews_csv / reviews-csv`、商品 `100013588055`、UTC `2021-09-11` 至 `2022-08-26`，固定原标注 profile、BGE-M3/1024 维、EmbeddingSpace 和 `quote-utf8-v1`。模型仍固定修订、离线缓存加载。未下载、安装、同步向量或修改评论。

已在现有 `.env` 仅配置以下三项；其他配置行原样保留，敏感值未输出：


`configured_agent_identity()` 在每个任务执行前读取 Worker 的 `env_file`；默认服务工厂按解释器/缓存/超时复用模型进程。四个成功语义任务属于同一 Worker，运行入口 PID 均为 **14500**，后三次 `model_load_ms=0`。故障测试结束后配置字节摘要恢复，正常查询继续复用原进程。

## 发现及修复

| 实际问题 | 最小修复 | 验证 |
|---|---|---|
| 语义结果在执行详情显示 `undefined [r1]`，没有具体内容 | 补齐 `semantic_evidence` 类型、标题、摘要、工具名及导出/追问映射 | 真实页面标题和详情正常；TypeScript 构建通过 |
| 回答已有引用，但无法展开定位评论上下文 | 在回答中增加“查看原文”折叠项；仅从已许可 reference 匹配对应候选，再展示原文及高亮 | A/E 真实页面展开成功；未许可候选没有被作为回答引用展示 |
| 冷启动只显示“准备执行”，等待含义不清楚 | 明确提示首次本地检索可能加载模型，请稍候 | 真实首次运行保持等待且成功；合成测试验证新提示 |
| 刷新/恢复分析历史后输入区回到基础问答，分析范围栏消失 | 按恢复的活动消息类型恢复模式；后续手动切换仍有效 | 真实刷新/会话恢复通过，合成 App 用例覆盖 |
| 编码失败只显示内部稳定码 `embedding_failed` | 转为可操作的本地检索配置提示，错误码仍放在折叠详情 | 真实失败任务页面复查通过，没有堆栈或凭据 |

引文折叠项核对公开引用中的 review/product/opinion/annotation/快照/文件行身份、quote 和区间。高亮采用 Python 字符索引对应的 Unicode code point，包含 emoji 的合成测试通过。完整评论只作为上下文展示，明确不作为新增支持事实；前端没有增加证据许可或语义推理。

## 页面、队列与范围行为

- 实际观察到提交 202/queued、running、succeeded；受控故障任务实际进入 failed。其结果没有正常回答或引文，配置恢复后的新任务成功。没有自动重试真实任务。
- `POST /tasks` 异步返回，`useTask` 每 **1500ms** 轮询活动任务，连接失败后每 **5000ms** 重连；单个 HTTP 请求为 **30 秒** 超时，没有整轮任务 30 秒截止。600 秒是模型请求上限。Vite 通过 `VITE_API_BASE_URL` 直连本地 API，没有测试反向代理；部署代理配置不在当前仓库验证范围。
- 首次模型等待期间页面有等待状态，未误报请求失败。刷新恢复原任务和回答，不重复 POST；新建会话消息为空，历史会话可恢复。手动切换基础问答仍允许；本轮不执行外部基础问答。
- 商品切换后实际提交参数为新商品 ID，`context_task_id` 没有继承旧商品任务。该请求由本轮私有范围边界在检索前拒绝，当前轮没有旧引文；历史轮仍明确保留自己的商品范围。**未执行其他商品的真实 RAG**。
- 数据集切到现有 `amazon-reviews-2023` 后新建会话为空，没有旧引文。切换过程只验证界面及元数据；范围外覆盖率请求主动阻断，没有读取新评论正文或执行新模型查询。
- 在 **1440/1024/768 × 900** 的真实 Chrome 页面检查回答、引用展开和范围弹层，无横向滚动，弹层位于视口内；对最终截图另行等待过渡结束并检查，未用过渡帧冒充稳定布局。

两处验收脚本问题保留记录：最初私有范围边界的错误响应缺 CORS，及 Ant Design 单选容器定位不准确；修正测试脚本后剩余交互验收通过。这些不属于生产 API/模型失败。另有一次测试脚本在基础问答模式等待任务响应，实际请求被本轮外部问答保护拒绝，未调用 LLM；不计为 RAG 任务。

## 最低可用结论与下一步

**当前已测单商品范围内，可从现有 React AI 助手日常提交受支持的评论检索和 SQL 问题，查看有来源的回答及原文。** 可以直接转向实际使用体验和语义覆盖优化，不需要新的评审平台或审批阶段。

保留的限制：确定性语义覆盖仍有限，长期/复杂命题可能保守拒绝；200 条索引不等于覆盖全部观点；本轮没有启用外部 LLM、未验证其他商品真实检索、生产 PostgreSQL 队列写入或部署代理。冷启动仍需等待，页面轮询/排队也增加端到端耗时。

正常启动继续使用项目已有 `run.py`/server 入口；RAG 配置现已就位。评论 RAG 测试选择“评论分析”，基础问答属于另一条可能调用外部模型的路径。本轮到此结束。
