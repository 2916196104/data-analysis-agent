## 4. Runtime 准入与来源缺口

### 4.1 契约不是简单格式转换

用保存的真实绑定 scope、当前 build_query_plan 对原24题纯离线重解析，**0/24** 同时满足 Text Evidence 所需的 fact_search/evidence/supported、有明确事实、无 uncertainty。例：Q03进入统计路径，Q18进入 opinion_summary，Q06是 retrieval_only，Q20/Q21为不支持的复合目标；不能只看 support_status 的字面值。

已有人工确认仍然有效，但它确认的是另一种 QueryContract 及原目标。下一次只对**选中的目标**制作可追溯的实验 Runtime 绑定：保留原事实描述、all_of/any_of、必要关系、条件和范围，关联原确认/修订；核对等价后冻结。不能把“制冷快”替代“制冷好”、把“无人跟进”替代“客服态度差”，或删去“炎热、运行较久、反复调期、同一评论”等条件。

如果需要重新表述/拆分目标，明确作为新的评估子问题，仅做该处语义等价核对；不冒充原题已自动解析成功。不修改正式解析器，不把其 unsupported/retrieval_only 自动升级。目标本身未知、统计/因果/总体能力问题继续不进入 Text Evidence；候选对象未知则是四状态中的 unknown，二者不可混淆。手工确认的实验目标质量也不能计作正式用户意图解析准确率。

### 4.2 快照足够读内容，不足以冒充当前来源

当前旧 strict inputs.json 实际为 **空列表**；57个 history_unproven 快照没有因人工发布而升级。P0 的 require_source_validated_result 要求由本次来源校验签发、内容未变的内存绑定，不能从保存 JSON、自算哈希或旧引用反造。

因此本轮无需数据库即可完成内容分析与选样设计，但要执行现有 TextEvidenceShadow 的真实业务路径，仍缺当前来源准入。本计划不新建历史封存/审批体系来“修好”旧快照，也不修改 source_policy 常量或伪造 _source_validation。

若后续需要最小只读源核验，授权边界应先限为：

- 同一 source/dataset/product/date/profile；只含最终清单选定的 review_id（首轮不超过30条）及其**完整当前有效观点集合**。
- 必要字段：评论全文/内容身份、日期、导入file/line；review/annotation/模型或人工观点ID、修订和处理状态、原 quote/范围、profile和有效集合摘要。用于识别正文/标注漂移，版本变化先剔除并报告，不在看过模型输出后改金标准。
- 不读其他商品，不同步/回填，不读取或生成新向量，不调用 BGE 或模型。旧 Top-K 仍是旧 Top-K，不把一次来源重验称为重新检索。

**现有直接 P0 检索入口不能承诺只读这些ID**：_PostgresSnapshot.corpus 会读取整个已选商品日期/profile范围的有效语料，且 search 上游会进行查询编码。未另行获得相应范围及本地编码授权，不得调用该入口来完成“最小读取”。若做限ID的来源适配，必须复用完整来源检查并合法签发本次绑定、先有离线测试；不能用 SyntheticRepository/假向量包装真实数据自证。该适配和任何数据库读取本轮均未实施。

## 5. 首轮有限评估集设计

主设计是从37评论/51观点池按目标和风险分层，选 **24 个目标契约×候选单元，上限30**；优先不同评论，确需同评论多事实时记录聚类，不按不同key增加独立评论数。冻结前允许数量更少；资料不足的分层标未覆盖，不造真实来源。

分为两条指标线，避免把定向挑选当检索成功：

1. **检索线**：复用原48组及原相关性标签，保留完整U/F顺序和空列表；独立性限制下的6张列表单独报告。它不花新的模型调用，也不重跑检索。
2. **语义/引用线**：挑选目标明确的真实候选形成固定挑战集，每请求一个明确 Runtime 契约、最多5候选，计划6–8个请求、**硬上限8个**。定向选入的非Top-K候选必须明示，不计算它们的新目标检索 Hit/Recall。若所选目标无法在8请求内组织，减少首轮范围并列缺口，不临时增加调用。

| 业务/风险分层 | 既有可复用线索 | 当前覆盖判断 |
|---|---|---|
| 制冷正面/不足 | Q11/Q12/Q20 的目标与原相关性/支持种子 | 可选样；速度、效果、长时间和条件必须分别核对，四状态尚未冻结 |
| 安装人员与客服角色 | Q02/Q03/Q18 的契约/原文；剩余37评论中18条有安装线索、14条有客服/售后线索 | 只说明可找角色反例，不等于已有14/18个金标准 |
| 配送及时/延迟 | Q05/Q06/Q07；剩余6条有配送词线索 | 可选样；首次到货、承诺调期、反复延迟不能互换 |
| 售后处理/无人跟进 | Q01/Q04；可复用部分支持种子 | 与客服态度分开，不能用旧维度标签代替具体事实 |
| 商品质量 | Q08/Q09/Q10；剩余5条有质量/故障词线索 | 做工、早期故障、耐用等不混为同一目标；覆盖待逐条阅读 |
| 同评论正负并存 | Q21及完整上下文；剩余4条含转折线索 | 不跨评论拼接；无关好评不能否决另一维度投诉 |
| 明确撤回/纠正 | 剩余池未命中本轮撤回/纠正词扫描，旧参考无该四状态标签或context观察 | **未确认覆盖**，不以合成案例或相反体验补齐；不能由关键词0推断全库不存在 |
| 否定/转述/假设/未知对象 | 剩余31条含否定词，1条有条件词、2条有不确定词，转述词扫描0 | 都只是线索，不是语义金标准；未确认的类型记未覆盖 |
| 无直接支持 | 原10个 no_known_relevant 问题和非direct发现 | 不等于 refuted，也不是全库无证据证明；需要逐候选复核 |

以上词扫描没有产生任何 expected_status。若找不到真实 refuted 或 unknown 标准样本，其召回/类内指标为 N/A，并阻止对相应能力作准入结论。

## 6. 增量人工标准与引用验收

不重审全部24/48旧审批，也不建新平台。复用原确认目标、事件、支持片段和理由，只为最终选中单元补充一份私有评估旁表：来源/目标版本、暴露状态、四状态、允许引用类型、语义充分依据及原人工记录指针。原参考不覆盖、不改标签枚举；新增四状态仅用于此次评价，不是新的 LLM 输出 Schema。

8个去重支持种子只有在事实、quote、全文及上下文政策一致且无冲突时才可继承为支持证据线索；其余候选不能因为未被引用就填 not_supported。partial、unknown、反例和可能撤回需要真实人工作判断。参考须在请求前冻结，评审时不看本次 Text Evidence 输出；模型不得生成或修订自己的答案标准。原相关性暴露/单评审人局限如实保留。

四状态标准沿用现有语义：

- supported：quote 直接报告该对象、说话者和目标事实；全文不能提供新支持。仅引用设备名、极性词或缺失角色/否定范围的片段不充分。
- refuted：同一候选的相关主张被明确否认、撤回或纠正；quote 内用 refutation_refs，quote 外同评论用 context_veto_refs。相反体验、后来改善、另一买家的意见均不自动构成撤回。
- not_supported：目标明确，但该候选没有直接支持，包含相反体验、明确不同对象、转述/假设且未报告本人目标体验；不能与 unresolved attribution 混同。
- unknown：说话者、对象、否定范围或上下文仍无法可靠确定；不能用猜测强制给出确定状态。

引用必须逐字、同key/同source identity、全文哈希和quote范围一致，以Unicode code point生成合法绝对区间，且原 B2 全通过。支持/quote反驳不越出quote；context veto只在同评论全文，不能补支持。允许不同但语义充分的精确片段，不把示例文字强制成唯一正确答案。

歧义按**实际所选 text 在允许范围内**判定，包括重叠匹配。模型选更长、充分且唯一的片段可通过；选重复短句则应拒绝，不能事后选第一处或自动改引文。合法区间也仍须单独审查语义充分性。

## 7. 三层指标与分母

| 层次 | 必报指标 | 分母/边界 |
|---|---|---|
| 检索 | 原相关性P@1/3/5、Hit@5、MRR；按目标事实的Top-K证据命中；U/F配对差异、空列表与无证据返回 | 原14个answerable的固定规则不改；完整qrels不足则Recall=N/A。复合目标要分别报告事实覆盖和必要关系满足，不能仅命中一个事实就当整题命中 |
| 判断 | 四状态混淆矩阵、整体/分层一致率；supported precision/recall；refuted precision/recall；未知强行确定率 | 单位为固定事实×候选，按评论聚类；U/F同证据不计两份独立样本。类别无样本或没有预测时相应比率N/A，不填100% |
| 关键语义错误 | **错误supported**、**错误refuted**各自数量、占所有该类预测的比例、对其他金标准类的假阳性率；相反体验误作撤回；遗漏明确撤回 | 同时报分子和具体分母，不能只报整体正确率。错误supported包含把unknown/撤回/无支持强判支持 |
| 引用 | 实际引用唯一定位率、来源/切片/Unicode合法率、B1/B2整请求通过率、引用语义充分率、歧义正确拒绝数 | 结构与语义分开；无引用状态不计为定位失败，不能用空数组提升引用成功率。缺少应有依据计失败 |
| 执行与保护 | 预算预拒绝、Schema/Provider/绑定/定位/B2失败数，超时/取消/usage未知，调用数/实际token/耗时P50/P95，v2回退与许可保护 | 失败不改写成unknown；结构失败的诊断标签仅unvalidated_diagnostic_only，语义混淆矩阵不收纳，正式准确率N/A |

同时报告“结构有效且有金标准的条件语义一致率”和“全部已冻结单元中结构有效且语义正确的完成比例”，避免删去结构失败后夸大效果；后者把失败计为未完成，不伪造四状态。冻结前因独立性/来源/目标/预算排除的数量另表披露，不隐去长评论或困难目标。

## 9. 成功原文留存、同步耗时与v2回退

### 成功路径的可复核性

现有成功路径仅保存规范化B1 judgments，原Text正文和正文哈希缺失，无法在事后逐字重解析新契约、检查模型是否省字段或复核转换前后差异。T组限制留在原报告，不能从B1反造原始响应。

### 同步用户问答

单次7.6秒不足以证明同步适用性，不能忽略检索、源核验、排队、重生成和尾延迟。最小后续方案是先保持v2即时结果，LLM仅异步Shadow观察；业务实测P95/超时率、成本和质量达标前，不把它加入默认同步关键路径。未来若确需同步，应先约定端到端等待预算，并在到期时原样回退，而不是承诺本次7.6秒为SLA。

### 是否只处理v2未确认候选

运行时可优先限制在**目标明确、来源有效但v2未直接确认**的候选，减少调用；目标未知或契约不支持的请求应澄清/保留原行为，不能交给LLM猜目标。本轮质量集仍保留少量v2直接确认的对照，并单列“全选定集”和“v2未确认子集”指标，避免只测难例后混淆总体效果。
