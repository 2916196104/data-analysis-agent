# AI 助手真实模型评测与 PostgreSQL 联调

日期：2026-10-30（Asia/Taipei）。本阶段完成真实供应商调用、独立 PostgreSQL 集成测试、实际业务库只读采样及浏览器联调。修复后 18 题首轮通过 17 题（94.4%）；剩余一题发生供应商超时，单独重试一次通过。该结果是固定小样本验收，不代表对任意问题的泛化准确率。

汇总证据见[阶段摘要 JSON](../output/playwright/review-live-20261030-final/stage-summary.json)。所有本阶段临时 PostgreSQL 集群已停止，测试数据库及其数据目录已清理；本机业务 PostgreSQL 服务保持运行。

## 范围与环境

- 执行模型：`Pro/deepseek-ai/DeepSeek-V3.2`，使用项目 `.env` 的现有供应商配置；提示词为 `review-agent-v2`。
- 数据库：本机 PostgreSQL 18.6。业务库现有 16,514 条评论、1,706 款商品、7,563 条模型标注、13,054 条观点。
- 在线题库：独立 `agent_test_*` PostgreSQL 数据库中的 96 条明确标记的合成评论，包含两款商品、两个月份、预置观点。数据来自既有 `scripts/frontend_fixture.py`。
- 真实模型仅接收合成测试上下文与合成原文。业务库仅在本机以只读连接查询，不将真实评论发送给供应商。
- 每题最多四次应用层模型调用，关闭 SDK 自动重试；真实 API 任务沿用当前配置的八次上限、一次 SDK 重试和 30 秒超时。这些设置只用于验收进程，没有修改 `.env`。
- 评测核对固定范围、预期工具、关键参数、结果引用和确定性校验；不以模型自报 `ok` 直接判为通过，也不评估评论情感标注准确率。

## 发现与修复

**证据 → 问题 → 修复：** 供应商原始返回把 `DEMO-A`、`DEMO-B` 拆为字符数组；[原始诊断](../output/playwright/review-live-20261030-baseline/diagnostic.json) 与[失败执行记录](../output/playwright/review-live-20261030-baseline/live/products.json)相互对应。既有范围校验拒绝了这些参数，模型重复错误并耗尽预算。

`ReviewTool.get_parameters()` 现在将当前授权商品的完整 ID 写入 JSON Schema 的 `items.enum`，并明确每项是一个完整 ID。空商品集合使用 `maxItems=0`，避免生成空枚举。执行层继续独立验证范围，不拼接错误字符，也不放宽权限。新增离线回归覆盖声明范围隔离、字符数组拒绝、完整 ID 接受和空集合声明。

修复后的商品对比和指定商品原文查询均在两次模型调用内完成。改动位于 `src/data_analysis_agent/agents/review_tools.py`，没有更改统计口径、HTTP API 或业务数据库结构。

**评测脚本修正：** 首两轮 API 检查的 TestClient 默认 Host 为 `testserver`，被项目现有的本机 Host 限制拒绝（403）。已将脚本客户端改为 `http://127.0.0.1`；[单独 API 复验](../output/playwright/review-live-20261030-api/report.json)和[修正后完整单题流程](../output/playwright/review-live-20261030-retry/live/evaluation.json)均通过。原始 `stages.json` 的失败退出码和日志保留，不将其改写为成功。

## 复现

需要项目 `.venv`、已安装的 PostgreSQL 服务端程序、前端依赖和可用 Chrome。`.env` 保留既有模型配置和业务 `DATABASE_URL`，无需测试管理员密码；入口会创建仅绑定 127.0.0.1 的独立临时 PostgreSQL 实例。

```powershell
.\.venv\Scripts\python.exe -m scripts.review_agent_acceptance --live --output ("output/playwright/review-live-" + (Get-Date -Format yyyyMMdd-HHmmss))
```

这条命令会消耗真实模型额度；按顺序执行 PostgreSQL 回归、固定题库、一个真实后台任务、业务库只读采样及模拟模型浏览器验收，保留各阶段退出码。可追加 `--case unlabeled` 仅重试该题，仍执行其余集成检查。`--pg-bin` 支持指定 PostgreSQL bin 目录。

直接使用已有独立测试实例时，可在当前进程配置 `TEST_POSTGRES_ADMIN_URL` 后通过 `scripts.evaluate_review_agent` 模块运行，参数与上述入口中的 `--live`、`--env-file`、`--output`、`--case` 一致；追加 `--business-readonly` 才读取业务库。不要把连接密码写入报告或提交到 Git。

评测结果逐题落盘；测试库在 finally 中删除，集群停止后清理其数据目录。历史日志与失败样本保留，以便定位回归。
