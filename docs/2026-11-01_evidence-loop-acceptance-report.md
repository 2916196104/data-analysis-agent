# Agent 证据补查与分析闭环：最小实现验收报告

本轮实现并验证了 **一次受控补查→独立校验→合并校验→事实重建→重新回答** 的闭环。P01、L02、T02 已通过真实本机 HTTP、持久任务队列、后台 Worker、既有只读工具及真实配置模型的完整链路；不是构造好的工具快照验收。

本轮止于最小闭环。本地语义表示只覆盖有明确原文支持的有限表达，不是通用深度理解或通用主题归并；未自动开展第四阶段，未完成真人回答质量验收。

## 1. 实施范围和数据流

实施前设计见 [最小设计](2026-11-01_evidence-loop-design.md)。保留 3.5 补充验收已有未提交改动，没有改写其验收结果或将其文件全部归为本轮成果。

执行路径为：

1. API 校验自然语言问题和任务范围，以既有幂等键入队；真实后台 `TaskWorker` 自动领取。
2. 原意图解析与原计划执行工具，原结果通过统一校验并压缩。原事务关闭。
3. `complete_evidence()` 复用 `assess_evidence()`。仅对明确内容分析目标补查，单纯原文分页或常规统计不擅自扩展。
4. 核对商品、维度、情感、日期、固定工具及参数模型、原任务剩余工具预算。最多一次周期、最多两项工具建议，无递归任务或自由 SQL。
5. 补查在独立只读连接中执行，每项独立校验；检查已有可比范围的样本计数没有变化。全部成功后统一验证合并结果，重新压缩并构建可信事实目录。
6. 关闭补查事务后生成回答。后端从已核验证据构建有限语义关系，将直接结论和原始统计/引文一起交付。模型失败时保留事实和可靠的本地描述，不声称模型生成成功。

队列复用现有 `analysis` 任务：补查是同一个已领取任务中的一个阶段，没有新建独立队列或改数据库。相同幂等键返回同一任务；公开读取只重建快照，不查询业务库、不调用模型。

需要共同范围确认或商品/维度/情感无法唯一确定时，返回具体澄清。首末窗口仅在唯一维度的已验证序列中确定，再核对自然日/月边界和原范围；不会自动扩大日期、选择其他商品或另开第二轮补查。

## 2. 隐私和细分查询的取舍

`get_aspect_drilldown` 会将原文发送给外部主题模型。**自动补查不新增这种外发**：其建议被明确转换为同商品、同维度、同情感的既有 `get_opinion_breakdown`，执行记录同时保存 `proposed_tool`、实际工具和转换原因。

精确观点分组沿用原去重计数与分母；没有将其冒充语义聚类，也没有重新计算“本地角色”的主题占比。现有显式主题归并能力和参数契约保留，不在本轮重新实现。

本地 `local_evidence_spans_v1` 只对完整、明确的表述建立关系：

- 包装：外箱状态、盒内固定、封口完整性；只有原文明确说商品完好时，才指出包装负向提及不都等于内件损坏。
- 物流：发货前等待、运输追踪、预约履约；逐条绑定商品，不能把甲的观点移到乙。
- 时间：绑定真实查询窗口，区分首末窗口中的问题内容，不能由此归因运营措施。

每项关系包含稳定 `relation_id`、规则版本、原事实引用、结果 ID、证据 ID、商品、日期、评论 ID、原文位置和引文指纹。严格匹配的是原文，不是仅凭主题名称猜关系；否定、模糊、未知或跨范围不一致的表达不强制归类。无法形成关系时明确说明证据表示尚不能可靠回答，保留原文和统计。

关系在模型返回后由后端计算，原文及新增语义衍生内容不进入回答模型。三个真实模型轮次捕获的全部 SDK 请求均未包含夹具原文或本地关系标识。本轮只使用隔离合成数据，未访问或向外部发送真实商品评论。

## 3. 真实 API/队列/Worker 验收

脚本使用真实 uvicorn 回环 HTTP 服务、真实持久 SQLite 任务队列和 `TaskWorker.start()` 后台领取循环。通过 HTTP 提交自然语言问题、重复幂等提交、轮询终态、公开读回并再次读取。**没有手动 claim、直接调用 `_execute`、注入计划或替换分析快照。**

使用临时导入并标注的 `insight-evidence-v1` 合成数据和 `Pro/deepseek-ai/DeepSeek-V3.2`。补查实际调用既有 SQL 分析函数；没有模拟工具统计或主题模型结果来通过这三题正向验收。自动路径不调用外部主题归并模型。

| 场景 | 原工具及自动补查 | 最终轮次实际工具调用 | 模型 HTTP 尝试 | HTTP 端到端耗时 | 结果 |
| --- | --- | --- | --- | --- | --- |
| P01 包装差评具体反映什么问题 | 一级负面统计→包装负向精确观点查询 | 3 次，含上下文；1 次补查 | 3 次 | 38.379 秒 | 补查、独立/合并校验、公开回答成功；回答模型超时，安全降级后仍显示可靠本地结论 |
| L02 两款商品物流差评发生在哪些环节 | 商品比较→每商品各一次物流负向观点查询 | 4 次，含上下文；2 次补查 | 1 次 | 4.716 秒 | 双方各自证据和环节归属保留，模型事实重点生成成功 |
| T02 按月变化及首末月份内容不同之处 | 物流月度趋势→1 月、3 月各一次观点查询 | 4 次，含上下文；2 次补查 | 3 次 | 22.279 秒 | 区分窗口内容并保留真实趋势；不推断改善原因，模型事实重点生成成功 |

三题每次均只有一个补查周期，独立和合并校验通过，重复提交返回同一任务 ID，公开重复读取不增加模型调用，业务数据库 hash 不变。最终本地离线完整链路复查也通过。

这里的工具次数包含 `get_analysis_context`，不是底层 SQL 语句条数。端到端计时包含 HTTP 提交、后台领取、执行和 0.1 秒轮询；不包含浏览器渲染、真实 PostgreSQL 网络或生产排队竞争。样本过少，不报告生产 P95。

证据：`output/playwright/evidence-loop-live-http-audit/report.json`，逐题 `P01.json/L02.json/T02.json`；前两轮完整保留于 `evidence-loop-live`、`evidence-loop-live-final`。

## 4. 实际回答示例

P01 的问题是“包装差评具体反映什么问题？”。一级统计原本只能说明 13/24 条成功标注评论涉及包装负面观点；本轮自动取得三种精确表述，分别为 6、4、3 条，分母是 13 条匹配评论，没有改成全评论主题占比。最终直接结论为：

> 已检索的包装负向原文涉及外箱状态、盒内固定、封口完整性，这些描述对应不同的包装现象。其中有买家明确自述外箱受压但商品完好，不能把包装负向提及全部解释为内件损坏。

原文包括“外箱压瘪但商品完好”“内衬移位导致配件在盒内晃动”“封口开裂”。“导致”在此仅是买家原文，不被升级为实际责任或客观根因。后端仍展示各表述真实数量、占比、评论编号及来源。

L02 最终将 `IE-LOG-A` 的发货前等待，与 `IE-LOG-B` 的运输追踪、预约履约分别绑定；没有把物流负面占比高低说成责任或真实服务水平差距。原比较分母仍为各商品 30 条成功标注评论。

T02 保留 2023 年 1—3 月物流负面占比 `12/30 → 6/30 → 3/30`；对应原文分别来自 `2023-01-01 至 2023-01-31` 的发货等待和 `2023-03-01 至 2023-03-31` 的预约偏差。只说明**这两个已检索窗口**的内容区别，不声称 2 月问题内容已查询，也不把负面减少归因于仓储、承运商或运营优化。

完整正文、统计、引文和本地关系绑定见 `output/playwright/evidence-loop-live-http-audit/answer-examples.md`。这些是工程验收与 AI 编写的直接性规则检查，不是已完成人工质量评阅。

## 5. 异常、只读与任务回归

以下八项使用同样的真实 HTTP、持久队列和后台 Worker，并显式注入故障；SDK 使用模拟响应，**不算真实模型攻击成功率**：

| 控制 | 实际行为 |
| --- | --- |
| BUDGET | 原任务剩余工具额度不足，补查零次，整体失败；不追加预算或无限重试 |
| QUERY_FAIL | 补查查询超时，原始查询校验保留用于审计；整体失败，不发布完整回答 |
| QUOTE | 返回中的原文被故意篡改，独立引文校验失败，拒绝合并 |
| WRITE | 在补查只读连接中尝试更新合成评论，被数据库阻止；业务库 hash 不变 |
| DATES | 注入原范围外的子窗口，在补查查询前拒绝，补查零次 |
| AMBIGUOUS | 三款范围中的“这两款”无法唯一确定，具体澄清，不执行补查 |
| PARTIAL | 真实提取观点后注入分类批次失败，任务 partial，公开回答不成功，不启动补查 |
| FAILED | 注入主题发现失败，任务 failed，不启动补查，不发布主题结论 |

八项均通过幂等提交与公开重复读取检查。补查失败时，不仅任务终态和公开接口失败，原始任务结果里的整体校验、公开视图也清除陈旧成功状态；原始校验保存在 `evidence_completion.initial_validation`。

证据：`output/playwright/evidence-loop-http-controls-final/report.json`。最终日期范围校验还验证真实日历日期，历史公开读取及会话恢复重建实际执行范围，拒绝以持久化范围字段扩大访问权限。

## 6. 模型调用与性能

没有只统计成功轮次。三轮合计捕获 **21 次 SDK 调用：12 次原规划、9 次回答草稿**；19 次返回完整响应，2 次回答草稿超时。最后一轮增加底层 HTTP hooks，实测 **7 次 HTTP 尝试、零内部重试**，其中 6 次取得完整响应、1 次超时。没有新增支持复核调用或主题模型调用。

前两轮只记录 SDK 调用，而规划 SDK 允许最多一次内部重试，不能冒充已经准确测量了其 HTTP 请求数。旧报告已标注这一边界，原 7 次计数保存在 `original_reported_external_requests`。全轮历史实际 HTTP 尝试的可证范围为 21—29 次，精确账单请求数未知；最后一轮的 7 次则是实际测量值。

已返回 usage 合计输入 39,118、输出 562 token。2 次 SDK 超时未返回 usage，历史未观测的潜在重试也不能按零消耗计费。没有完整账单，不估算金额。

| 轮次 | P01 | L02 | T02 | 评测墙钟 |
| --- | --- | --- | --- | --- |
| 第一轮真实模型 | 32.823 秒，llm | 4.856 秒，llm | 12.935 秒，llm | 53.255 秒 |
| 第二轮真实模型 | 46.998 秒，fallback/timeout | 5.700 秒，llm | 17.948 秒，llm | 74.501 秒 |
| 最终 HTTP 审计轮 | 38.379 秒，fallback/timeout | 4.716 秒，llm | 22.279 秒，llm | 68.711 秒 |

P01 第二轮规划请求分别约 22.779、2.501 秒，回答草稿约 15.090 秒后超时；最终 HTTP 审计轮也发生回答超时。本地关系使其不丢失已核验的包装内容分析，但并没有解决模型服务延迟，也没有把 fallback 改标 llm。

成功返回的草稿只负责重点选择，本轮本地语义关系不是模型自由解释。功能上的三题成功不能当作真实模型洞察质量全面提高。详细调用与累计 token 见 `output/playwright/evidence-loop-live-http-audit/all-live-costs.json`。

离线 SDK 调试、故障控制和最后的离线完整链路复查外部调用均为零。早期离线夹具曾错误嵌套 `result_ids`，修复夹具后通过，未放松生产响应验证。早期回归发现普通组合原文请求被额外补查，已收窄到明确内容分析目标；基线分页也不升级为主题分析。

| `scripts/accept_evidence_loop.py` | 真实 HTTP/后台 Worker 验收、离线故障控制、请求/耗时/幂等/只读审计 |
| 本报告与设计报告 | 设计、结果、边界和复现路径 |

内部结果新增 `evidence_completion`；补查结果记录 `execution_scope`，合并计划记录对应范围。公开回答新增默认空数组的 `evidence_relations`，由原始快照重新核验和计算，不信任持久化关系文字。没有新增 API 入参、数据库迁移或任务类型。

前端无需布局修改：直接结论仍显示在已有 summary，原统计、原文和执行详情沿用原区域。没有重构意图、标注或主题模型，没有修改 `.env`。

## 8. 测试与剩余边界

- 阶段一至三、3.5 及本轮受影响回归共 203 项全部通过（76.09 秒）；日志为 `output/evidence-loop-regression-verified.log`。随后审计分段对齐修改另跑新增 9 项测试，见 `output/evidence-loop-audit-regression.log`。此前曾出现 1 项额外补查回归，已修复，记录未删除。
- 前端 23 文件、206 项通过，构建通过（15.33 秒）；保留已有 jsdom 和 bundle 大小提示。本轮未改布局，未重复浏览器多视口 E2E。
- 正向三题与八项故障控制均走真实回环 HTTP 和后台领取；最终离线三题再核对最终守卫。模型真实测试与离线故障注入分别统计。
- 真实 PostgreSQL、生产角色权限、并发负载、断电恢复和真实评论联合模型测试本轮未验证。SQLite 的只读证明不冒充生产 PostgreSQL 权限验收。
- 分事务补查会核对已知可比样本计数、范围及标注身份，不能证明并发人工修订中“计数未变但语义改变”完全没有发生；这不是跨事务 MVCC 原子快照保证。生产并发一致性仍需单独验收。
- 本地语义是有限、保守的完整表达规则，未覆盖任意口语、反讽、隐含关系、混合否定和复杂因果。不能识别时明确不足，不补猜。未新增角色主题的全量分类或占比。
- 本轮无人类逐题质量验收。可以交付为“最小受控证据闭环已通过合成工程验收”，不能交付为“通用深度洞察已达标”。本轮结束，不自动进入第四阶段。
