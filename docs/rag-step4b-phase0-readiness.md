### 4.2 sufficient / limited / insufficient

参考状态按**当前可见候选与上下文、所问目标事实**人工评定，不判断整个商品数据是否可回答。

| 状态 | 定义草案 | 必须限制的结论 |
|---|---|---|
| sufficient | 有有效、可定位的直接证据，支持拟陈述的核心事实及必要对象、极性、时间或关系条件；存在性问题可由直接实例支持 | 只确认在指定证据范围找到实例；不扩展为总体占比、长期耐用性、因果或绝对不存在 |
| limited | 至少一个所问目标事实得到直接支持，但复合问题的其他目标、时间或关系条件未获支持；输出须逐项标明支持与缺失部分 | 只能许可已支持子结论，不能把泛化相似或无关信息包装成“部分回答” |
| insufficient | 没有直接支持所问目标事实，或候选为空、全不相关、仅主题相近、对象/极性冲突、关键条件均缺失、来源无效 | 对核心问题拒答或请求澄清；不把“当前未找到支持”写成“完整语料没有这类反馈” |

仅有 1 分候选不能自动升级为 limited；须有直接支持所问某一子结论的证据。存在 2 分也不自动等于 sufficient，例如噪声反馈不自动证明影响睡眠。mixed 必须核对同一评论的正负关系，不拼接不同评论。重复观点不增加独立来源数。固定 cosine distance 阈值不属于本草案；相似度不当作相关性概率。

现有标签只提供相关性参考，**没有三状态或逐事实充分性的人工金标准**。E1 需单独人工填写 `reference_state`、`supported_target_fact_ids`、`required_fact_ids`、来源支持关系、上下文版本和确认状态；无法判断的记录为 unjudged。此处只定义协议字段，不创建真实充分性标签、不代替人工打分。

已复算的 48 列表分布：有 2 分的 28 个、非空且全 0 分的 10 个、含 1 分但无 2 分的 8 个、空列表 2 个。它们是诊断分层，不是自动生成的充分性标签。前序计划点名的 Q03/Q19/Q21/Q23 两模式共 8 个全 0 列表只是其中子集；另有 Q17-U、Q16-F，共计 10 个。拟议“全 0 列表拒绝核心结论”是待人工批准的功能要求，不宣称已经实现或验收。

### 4.3 无支持回答与过度拒答的统计

E1 尚无自由文本回答模块，因此以下“回答”准确指**输出的回答许可及目标事实范围**，不能称线上错误回答率。`sufficient` 和 `limited` 都算许可回答，后者不能从风险统计中隐藏。

记 H 为人工已确认、上下文与版本匹配的有效 query-mode 集合；Gᵢ 为人工确认可支持的所问目标事实集合；Rᵢ 为回答所需的完整必要事实集合；Dᵢ 为判断器声明许可的目标事实。U 为 H 中 Gᵢ 为空的列表，S 为 H 中 Gᵢ 非空的列表，A 为 H 中判断器输出 sufficient 或 limited 的列表。充分性参考不能依待测输出反向设定。

| 指标 | 分子 / 分母草案 |
|---|---|
| 无支持场景的回答许可率 | U 中输出 sufficient 或 limited 的列表数 / U 的列表数 |
| 全部许可中的无支持结论率 | A 中 Dᵢ 含不在 Gᵢ 的目标事实、未映射证据，或宣称 sufficient 但未满足 Rᵢ 的列表数 / A 的列表数；U 中的任何许可也计入分子 |
| 过度拒答率 | S 中输出 insufficient 的列表数 / S 的列表数；对支持部分子问题却全部拒答同样计入，不只检查 sufficient 参考 |
| 全不相关列表的核心拒答率 | 人工复核的非空全 0 分列表中输出 insufficient 的数量 / 该类有效列表数；空列表另列，避免空集被算作“全 0” |
| 状态一致率 / 有限结论质量 | 与三状态人工参考一致的列表数 / H 数；limited 另报已支持事实覆盖与越界，不能只看状态名 |
| 评审与输出覆盖 | 已确认人工参考数 / 应评 48 列表；合法预测数 / 应输出 48 列表；失效、缺失、错误输出逐项列数 |

分别报告 U/F，各有效分母、无支持数、许可数及拒答数；只在同 query、两模式参考与输出都可判断时给配对差值及配对数。候选策略间也在相同 query-mode 上配对；不得把 U/F 合并的 48 个相关列表当 48 个独立 query 宣称泛化有效。

未评审不当作无支持，零分母保持 N/A。运行错误、非法状态、缺失预测不能悄悄从主结果移除或冒充正确拒答；计入覆盖失败，另报可判断子集及分母减少原因。若缺预测或参考未齐，不宣称完整验收。现阶段没有 E1 输出与人工充分性参考，以上效果指标均为 **N/A**；不将 14 个 answerable 或 20 个 no_known query-mode 直接转换成充分性真值分母。

### 4.4 实验输入、输出及来源要求

输入登记至少绑定 protocol_version、experiment_id、baseline_run_id、manifest/scope/空间/builder、标签参考哈希、当前代码版本、context_policy、查询契约版本及输入哈希。人工 relevance grade、note、reviewer、evidence_status、旧 metrics 和充分性参考答案只给独立评估器，**不进入候选判断器的决策输入**。人工冻结过滤可作为诊断上下文，但不能称已实现自动意图识别。

每个输入候选须能回指冻结 query/mode/rank/key、review_id、annotation_id、观点来源及修订身份、effective_snapshot_sha256、字符区间、embedding_input_sha256 和 evidence_ref。按归档 run 白名单核对，不接受同名 key 下替换的片段；同评论原文不一致、来源失效、scope 不符、遗漏或重复候选时记录错误并停止该实验的有效发布，不返回看似完整的部分结果。

输出草案包括：experiment_id、query_id、mode、输入哈希、判定状态、许可的目标事实、缺失条件、每个事实到候选 key/字符区间的引用、reason_codes 和执行状态。所有引用必须来自该列表实际可见输入；不能借用另一模式候选、全量归档或人工备注中的信息。合法解析和引用正确仅是结构性检查，是否直接支持结论仍需人工评审。

E1 首轮不从在线数据库补查，也不扩大候选集合。如果未来新实验产生新候选或改变证据上下文，必须新建运行与人工参考，未判定仍为 N/A；不能修改本基线标签，也不能沿用 no_known_relevant 推导新候选必为错误。
