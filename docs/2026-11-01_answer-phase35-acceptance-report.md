# 阶段 3.5：回答生成稳定性与质量验收

日期：2026-11-01。结论：**事实回答的稳定性门槛达到，深度解释质量尚未得到充分证明，不建议据此直接进入第四阶段。**

最终真实配置模型评测覆盖 43 个固定合成案例、37 个不同的数据快照。26 个需要模型选择重点的案例均完成，非预期降级为 0/26；其余 17 个按实际证据采用零调用统计、数据不足或澄清路径。相同的 26 个模型适用案例中，第三阶段基线降级为 18/26。最后一轮没有发布自由解释，不能把这个结果描述为“洞察准确率 100%”。

用户两轮真人评阅改变了本阶段的质量标准：优先发布有依据的事实，新增文字必须有增量信息。已经落实样本/覆盖率区分、单维度不得冒充总体排名、有限区间趋势、零匹配负面观点及去重口径等修正。未更改第一阶段意图解析、第二阶段主题归并、数据库、Agent 框架或前端布局。

## 3. 最终生成与保护流程

1. 继续使用已验证分析快照，不查询新数据、不重新执行语义归并。
2. 模型只选择 F1/F2 等短引用及有限解释；后端恢复稳定事实 ID。只做确定的 JSON 围栏、别名、重复 ID 和已知实体规范化，不修补任意非法 JSON，不把未知引用替换为合法引用。
3. 数字、分母、商品、日期、维度、主题和原文均由可信目录注入或核验。精确绑定商品 ID 后再检查数字，避免 S35-A、P1 等被误认为新增统计。
4. 事实正文、来源、范围和情感继续通过原 AnswerValidator。未知引用、伪造数字/引文/来源、样本外推、确定因果等保护保留。
5. 仅计数/方向或名称套用定义，没有额外解释证据时，不允许发布自由解释，记为 `no_incremental_evidence`。主题定义是否真正有增量仍需语义判断，不声称这个门槛是完整语义证明。
6. 有具体内容的自由解释与建议仍需独立复核；只等于已有命题的文字由程序验证并避免重复。重复项记为 `redundant`，不计入解释发布率。逐条拒绝不删除其他已核验重点或已经通过的解释。
7. 无效解释、复核失败或超时安全降级；不保存/发布无效模型正文。partial/failed 在生成前阻断，insufficient_data 保持具体说明，sample 不得当 full。

每轮最多两次请求，重试也占额度，SDK 自带重试关闭。默认单请求仍为 15 秒、整轮独立预算 30 秒；草稿/复核输出上限从 1400/500 调整为 360/280 token。输入仍逐请求受 16000 字节默认预算约束。未通过延长超时制造成功率。

SDK 超时与剩余时间检查不是可抢占的严格墙钟上限。实测包含客户端创建/关闭等开销，早期出现超过 30 秒的回答；报告保留这些数据。数据库在回答模型调用前关闭，测试继续证明这一点。

## 5. 支持性复核与真人质量

旧基线实际发起 12 次复核，8 次最终发布解释，可观察通过率 8/12。第一版短协议在完成复核的 18 条解释上曾得到 18/18 支持，但用户四题评阅揭示其中有重复和无依据内容，证明“模型复核通过率”不能等同于质量。

用户明确偏好四题的保守事实版，意见详见[真人评阅记录](2026-11-01_answer-phase35-human-review.md)。强化提示后仍发生错误，才增加代码证据门槛。最终固定集没有符合额外解释证据门槛的已发布解释，因此其语义复核通过率为“不适用”，不能写成 100%。

另用一个经过实际工具/来源验证、具有具体主题定义的合成正例运行真实模型：草稿和复核均执行，共两次请求，13.404 秒；复核判为重复，正确省略，未发布解释。这证明复核路径没有被删除，**不证明有价值解释的发布能力已经验收**。单元测试和浏览器模拟模型覆盖了支持性通过/拒绝、部分接受及展示分支，不能代替真实质量结果。
