# 使用评论标注工作台

在本机网页按商品、评论时间、维度、情感和处理状态筛选评论，分页查看原文与观点，确认或纠正模型标注，并查看各商品的标注进度。

**业务库升级由你执行。** 工作台不自动建表、不读取 `.env`、不调用模型；复核只写新增的人工记录表。此次开发和浏览器联调使用临时模拟库，业务库未升级，已有销售、评论导入和模型标注入口保留。

## 启动工作台

### 1. 备份现有数据库

先停止导入、模型标注和工作台进程，再在项目根目录 PowerShell 执行。停止写入后使用 SQLite 的备份接口，避免直接复制正在写入的文件。

```powershell
Set-Location E:\AllProject\data-analysis-agent
.\.venv\Scripts\python.exe -c "import sqlite3; from pathlib import Path; from datetime import datetime; p=Path('data/private/reviews.sqlite3').resolve(); target=p.with_name('reviews-before-workbench-'+datetime.now().strftime('%Y%m%d-%H%M%S-%f')+'.sqlite3'); source=sqlite3.connect(p.as_uri()+'?mode=ro',uri=True); dest=sqlite3.connect(target); source.backup(dest); dest.close(); source.close(); print(target)"
```

备份文件留在 `data/private/`，不会进入 Git。请确认上面的路径是你实际使用的业务库。

### 2. 显式增加人工复核表

已有商品、评论及模型观点表时，只需要执行：

```powershell
.\.venv\Scripts\python.exe -m data_analysis_agent.api.workbench init --db data/private/reviews.sqlite3
```

首次成功返回 `created=true`，重复执行返回 `created=false`。该操作原子增加三张表和索引，不修改原有表、记录、模型观点、`PRAGMA user_version` 或标注 schema 版本：

| 新表 | 内容 |
| --- | --- |
| `review_workbench_schema` | 独立工作台版本，首版为 1 |
| `review_human_reviews` | 每次确认或纠正的复核人、备注、时间、关联模型标注和上一条人工记录 |
| `review_human_opinions` | 每次人工操作保存的完整观点快照，包括原文位置 |

业务库不存在时不会自动创建；缺少模型观点表时，请先按 [观点标注说明](review-labeling.md) 执行 `review_label_cli init`。页面启动、查询和保存都不会隐式升级数据库。

### 3. 启动本机服务

```powershell
.\.venv\Scripts\python.exe -m data_analysis_agent.api.workbench serve --db data/private/reviews.sqlite3
```

在浏览器打开 [评论标注工作台](http://127.0.0.1:8765)。终端保持运行，按 `Ctrl+C` 停止。端口占用时可指定 `--port 8766`，随后打开对应端口。

无需新增依赖，无需重新安装项目，以上 `python -m` 即可使用。如希望注册 `review-workbench` 快捷命令，由你执行 `pip install -e .`；它只是等价入口。

本工作台仅绑定 `127.0.0.1`，用于单机操作；没有账户登录，复核人是操作者填写的文本。它不适合作为共享或公网服务。页面有来源检查和提交凭证，评论及备注按纯文本显示；没有第三方脚本或远程资源。

## 筛选和查看评论

1. 顶部选择“模型 / 提示词版本”。默认选取最近产生标注尝试的模型配置；模型、服务地址和提示词版本共同决定范围，不混合不同版本。
2. 按商品、起止日期、观点维度、情感、处理状态及人工复核状态组合筛选，点击“应用筛选”。日期使用评论发布时间的 **UTC 日期**，开始和结束日期均包含当天，不使用导入时间。
3. 每页可选 10、20、50 或 100 条，按评论发布时间倒序、ID 倒序排列，使用“上一页 / 下一页”。筛选变化后回到第一页；页数缩小时自动回到有效页。
4. 点击“查看原文与复核”，在详情中查看完整正文、当前有效观点和原文来源。点击观点旁的“定位原文”高亮连续片段，支持中文、换行和 emoji。
5. 展开“原文来源与模型记录”，查看输入文件、SHA-256、物理行号、模型原始观点及模型尝试历史。网页不提供打开任意本地文件的接口。

| 处理状态 | 含义 |
| --- | --- |
| 待标注 | 非空评论在所选配置、当前内容版本下尚无尝试 |
| 标注成功 | 已有成功模型结果，包括成功但无观点的结果 |
| 标注失败 | 已有失败尝试且没有成功结果，详情可查看错误代码 |
| 空正文 | 导入时正文为空或仅空白，不进入模型处理队列 |

人工状态独立分为“待复核 / 已确认 / 已纠正”。没有成功标注的评论也没有人工复核记录，但不允许确认或纠错；先使用原有模型标注命令处理。工作台本身不启动模型批次。

**筛选使用当前有效观点**：有人工复核记录时取最新快照，否则取该配置的模型观点。维度和情感必须匹配同一条观点。例如“使用效果正向、包装负向”的评论不会匹配“使用效果＋负向”。每条评论最多出现一次，不会因多个观点重复分页或计数。

同一个商品 ID 在不同数据集版本中按独立商品条目显示，避免把不同导入版本混在一起。没有模型标注记录时仍可浏览原文，非空评论显示为待标注。

## 确认或纠正观点

只复核所选配置下、与当前正文一致的成功标注。操作前填写“复核人”，可以添加备注。

| 操作 | 保存行为 |
| --- | --- |
| 确认模型原始结果 | 把模型原始观点复制为新的人工确认快照，不采用尚未保存的编辑内容 |
| 保存人工纠正 | 把编辑区的完整观点列表保存为新的人工纠正快照 |
| 删除全部观点后保存纠正 | 人工判定没有可支持观点，保存空列表；筛选不再回退使用模型观点 |

纠正时可以修改维度、情感和片段，添加漏标观点或删除多余观点。可以先在评论原文中选中文字，再点击“用所选原文添加观点”。每次最多 30 条观点，每段最多 2,000 个 Python Unicode 字符。

例如模拟评论“好用，包装破了”，模型只提取了使用效果正向：

1. 点击“添加观点”，选择“包装”和“负向”。
2. 原文片段填写 `包装破了`，保留已有使用效果观点。
3. 填写复核人和备注，点击“保存人工纠正”。
4. 当前有效观点变为两条；模型原始观点仍为一条，人工历史增加一次。

片段必须逐字存在于正文，不接受改写、翻译或拼接。服务端计算起止位置，满足 `text[quote_start:quote_end] == quote`，任一观点无效时整次操作不保存。

保存后商品已复核数量、筛选列表和详情会更新。如果纠正后不再符合当前筛选，该评论会从列表移出，详情仍可查看刚保存的结果。编辑内容必须点击保存才会入库，切换评论或刷新前请先保存。

人工记录只追加，不覆盖模型记录或旧人工结果。最新人工记录决定页面有效结果；再次“确认模型原始结果”会恢复使用模型观点，并保留之前纠正历史。不同模型配置分别复核；正文内容指纹变化后，旧结果保留在模型历史中，但不再用于当前筛选和进度。

两个人或两个窗口同时编辑时，服务端检查上一条人工记录 ID；后提交的旧页面收到冲突，不会覆盖先提交的结果。重新打开评论、核对新结果后再提交。

## 查看商品进度

顶部进度始终按 **全库＋所选模型配置＋当前评论内容** 统计，不受下面商品、日期、维度等筛选影响。

| 指标 | 统计口径 |
| --- | --- |
| 评论总数 | 商品下所有唯一评论，包括空正文 |
| 成功 / 有正文 | 成功模型评论数 / 可处理的非空评论数；成功无观点也计入成功 |
| 待标注、失败、空正文 | 三种模型处理状态分别计数 |
| 已复核 | 当前成功标注存在人工记录的评论数；同一条重复复核仍只算一条 |
| 标注完成率 | 成功评论数 / 非空评论数；无有效正文时显示“无有效正文” |

“已复核”表示存在人工决定，不代表模型准确率。命令行 `review_label_cli evidence` 继续展示模型原始历史；`status` 保留模型原始计数，并增加有效观点数和复核数。后端可使用只读 `query` 查询同一模型版本下的最新有效观点，详见 [按范围查询评论](review-query-scope.md)。

## 排查启动或保存问题

| 情况 | 处理 |
| --- | --- |
| 提示工作台表未初始化 | 由你先执行本页 `init` 命令 |
| 地址已占用 | 使用 `serve --port 8766` 并打开新地址 |
| 列表没有结果 | 检查模型版本、UTC 日期及是否同时指定了维度和情感；尝试“重置” |
| 只有待标注评论 | 继续运行原有标注 CLI，完成后点击“刷新数据” |
| 原文校验失败 | 从正文复制完整连续片段，保留原始空格、标点、大小写和换行 |
| 提示记录已被复核 | 重新打开评论，基于最新结果编辑 |
| 页面凭证失效 | 服务重启后刷新页面 |
| 数据库暂不可用 | 稍后重试，避免同时运行多个写入任务，检查库版本和目录写入权限 |

`init/serve` 正常退出码为 0，文件、数据库或启动错误为 1，参数错误为 2。HTTP 查询参数和观点格式错误为 400，未知记录为 404，复核冲突为 409，来源或凭证错误为 403，数据库暂不可用为 503。

新增 13 项测试使用临时 SQLite 和本机 HTTP，覆盖显式升级、旧版本保留、日期边界、稳定分页、商品版本隔离、同观点筛选、人工快照、空观点、同时提交冲突、Unicode 原文位置、模型记录保留、进度和请求校验。加上已有销售和评论测试，76 项全部通过；不调用线上模型。

浏览器使用独立模拟库完成分页、组合筛选、确认、补充遗漏观点、人工结果筛选、原文高亮和复核历史验证。模拟界面联调不代表真实评论标注准确率评测。工作台使用 Python 标准库 HTTP 服务，首版适用于当前几千条评论的本机复核，没有新增用户管理、导出、模型调度、趋势告警或销售关联分析。
