## 正确性、事务与异常

- 首问冷/热各 2 条引文，共 **4 次公开引文出现记录**（2 条不同引文），逐条核对原文切片、review_id、opinion_key、annotation、快照及导入文件/行身份。`validate_retrieval()`、`read_public_analysis()`、`read_public_answer()` 全部通过。
- **12/12** 公开回答与 P3-A 完全相同；首问仍只表达存在买家反馈，未升级为全体质量结论。其他问题没有新增无证据许可。SQL 分母 215、前三维度 135/109/104 及完整返回数据不变。
- 编码前、编码后及约 20ms 间隔共采样 **3350 次**，受测业务连接均无活动事务。源码流程先 rollback 范围规划事务，编码后重新 BEGIN 只读 RR，再校验当前来源；采样不声称捕捉了任意亚毫秒状态。
- 本轮未观察到模型、来源、引用、许可、SQL 或执行失败；没有外部 LLM 调用。每问错误即停止的保护未被触发。
- 五个模型入口进程均在关闭后退出；清理记录 `returncode=1` 是现有 `close()` 主动终止进程的结果，不能解释为请求执行崩溃。结束后只读进程列表中已无本次模型/驱动 Python。

### 内存观测限制

本次测量补充得不完整：Windows venv `python.exe` 是启动器，实际 Python 是子进程。`Popen.pid` 对应的 RSS/peak **约 4.3MiB 仅属于启动器**，不能报告为 BGE-M3 内存。运行期间已用系统进程树确认此关系（例如入口 29364 → 实际 Python 22152），但未及时取得加载后实际子进程的完整内存采样。

因此，**本轮实际模型 RSS/峰值为 N/A**。P3-A 的约 1.7GiB 只能作为旧结果参考；未填入本次数据。原始 measurement 保留，旁边的离线复核明确标记该限制；没有为补测增加调用。后续实际使用时，将内存采样指向实际 Python 子进程即可修正观测，无需改变模型或许可规则。
