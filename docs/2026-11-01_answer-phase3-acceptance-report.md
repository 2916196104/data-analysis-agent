日期：2026-11-01。范围仅限回答生成、必要的追问目的传递和展示适配。

**结论：工程链路和安全回归通过；真实模型的回答质量验收尚未通过。** 新流程已经允许有引用的自然解释，并保留统计绑定、证据验证、样本限制及失败保护。真实模型合成测试的降级率仍高，不能据此宣称整体洞察质量已经提升。本阶段在此停止，不开展第四阶段。

## 2. 数据流程和契约

1. 已有只读工具与统一校验形成可信快照；不复用失败轮次的未验证数据。
2. 在原 AnswerFact 上建立稳定事实 ID，绑定结果 ID、指标/分母、商品/日期范围、维度/主题 ID 和定义、证据 ID、完成状态、sample/full、覆盖及限制。
3. 简单正负统计、普通优缺点和数据不足继续零回答模型调用。趋势、同口径比较、多个二级主题及明确解释请求可进入新流程。
4. 草稿只包含 `schema_version=2.0`、`focus` 和至多两条 `insights`。重点最多八项，默认优先覆盖请求商品、维度和情感；比较先保留可比关系，同时保留双方问题或无数据事实。
5. 模型解释引用已选事实 ID，通过 `[[finding:0123456789abcdef0123.label]]`、`.aspect`、`.evidence` 形式选择后端值，实际 ID 必须来自目录。数字、商品、日期、主题名称和引文由代码生成。已知一级维度的引号名称精确匹配后重新绑定为 `.aspect`，避免把目录实体误当评论引文；任意自由引文继续拒绝。代码拒绝无效引用、未绑定数字/引文、样本外推及明显确定因果等文字。
6. 存在自由解释时，再做一次独立支持性复核。复核需覆盖每条解释，全部支持才发布；不能用复核修改统计。语义复核是另一条独立请求，使用相同供应商/模型，不是形式化证明或人工确认。
7. 组装事实主结论和选定统计，解释与建议分别标注。解释失败则保留可信事实，不保存或发布无效模型正文。统计、证据和执行记录仍在原有展开区域。

外层 PublicAnswer 继续为 `schema_version=1.0`，仅新增有默认值的 `insights` 数组；现有字段与任务提交接口不变。原 v1 草稿继续按原白名单验证。已确认查询内部 JSON 的 `question` 可选、最长 4000 字，缺失或无效时使用原有目的文本，不影响查询参数。

本地事实目录拥有原文绑定；回答模型输入不包含评论原文、完整正文、私有标注地址或调试轨迹。主题定义属于已有分析结果，只在获准的调用环境使用。本次所有外部测试数据均为临时合成夹具。

## 3. 状态和发布保护

| 状态 | 行为 |
| --- | --- |
| complete + full | 只描述匹配的已标注评论，主题仍为模型候选，保留去重分母和未归类数量 |
| complete + sample | 摘要明确“非随机样本”，占比说明使用纳入样本分母，明确不得视为总体比例 |
| partial / failed | 回答模型前拦截，不提升为完整成功；已核验事实留在既有详情/诊断契约中 |
| insufficient_data / 无可发布主题 | 零回答模型调用，具体说明暂无可发布主题或成功标注，禁止编排名 |
| 模型超时、Schema/引用失败、复核拒绝、预算耗尽 | generation_status=fallback；保留事实，记录 draft/support_review 等失败阶段 |
| 历史公开读取 | 零模型调用，重建事实；不把已存支持性标签当作语义证明，因此去掉自由解释。原任务快照仍保留运行时核验回答 |

历史公开接口会比运行时任务回答更保守，这是本阶段的明确限制。未引入签名、额外存储迁移或以重新调用模型恢复历史解释。

| --- | --- | --- |
| 好评主要方面 | 使用效果、物流、价格及各自分母 | 简单问题继续直接给结论，零模型调用；数值和口径保持一致，没有宣称自然语言提升 |

| 有充分合成时间序列 | 包装波动、物流下降 | 保留代码计算的变化、相邻区间与分母；该充分样本案例只做模拟模型测试，没有真实模型质量结论 |
| 无充分证据 | 无成功标注/有效观点 | 保留具体原因，零调用，不输出无关通用能力列表；多个限制仍有可精简空间 |
| 优缺点 | 正负观点精确文本分组 | 继续安全展示已有证据；普通请求未强制调用模型，也未重新执行二级归并 |

合成二级主题实例（不是美的真实商品结论）：

> 本次匹配的已标注评论中，具体评价主要体现在制冷速度、运行噪声，这些是模型归并的候选主题。
>
> 制冷速度：2 条去重评论、3 条观点，占该维度该情感匹配评论 50.0%（分母 4 条）。代表原文：“降温很快”（评论 #14）。
>
> 运行噪声：1 条去重评论、1 条观点，占该维度该情感匹配评论 25.0%（分母 4 条）。代表原文：“运行声音小”（评论 #14）。

sample 版本将摘要明确限定为非随机样本，正文分母改为“纳入样本评论”，保留“样本占比不能视为总体真实比例”、未经人工确认及未归类 2 条的说明。

独立质量评审对两个案例交替 A/B 顺序，使用单独提示、不提供新旧标签，评价相关性、重点覆盖、支持性、数字引用、抽样限制、简洁性各 0–2 分。校准轮得到：比较案例改造后 12/12、基线 7/12；主题案例改造后 12/12、基线 11/12。**不能把这些分数当作准确率**：同一模型存在相关偏差，评审对比较基线提出的部分数字/措辞批评并不充分，而且打分时的新回答主要是确定性降级结果。最终补齐比较双方发现、收紧提示后的版本未再进行外部盲评。没有真人评审，只有本次 Agent 对九题前后文本的阅读核对及上述独立模型评审。

## 7. 复现与剩余限制

离线固定评测：

```powershell
.venv\Scripts\python.exe -m scripts.evaluate_review_answers --output output/playwright/answer-phase3-offline-recheck
```

外部模型合成评测（会使用当前配置的外部服务，仅构造临时合成数据）：

```powershell
.venv\Scripts\python.exe -m scripts.evaluate_review_answers --live-synthetic --independent-review --output output/playwright/answer-phase3-synthetic-recheck
```

仅指定三个或一个案例可使用 `--live-cases B-topics-full B-topics-sample C-comparison`，避免无必要重复全部模型调用。真实库本地检查：

```powershell
.venv\Scripts\python.exe -m scripts.answer_facts_readonly --output output/playwright/answer-phase3-postgres-recheck
```

浏览器隔离验收：在前端目录将进程环境 `E2E_ANSWER_PHASE3=1` 后运行已有 `node tests/pros-cons.e2e.mjs`。它使用合成数据库和模拟模型，不连接真实评论模型链路。

剩余限制：

- 真实模型协议遵循、延迟和解释发布率未达标，尚需有界的提示/输出长度与供应商性能校准，之后才能谈规模化质量提升。
- 支持性复核与规则只能降低风险，不能证明全部自然语言推断。仅对已知一级维度的引号名称进行精确绑定，其他未绑定引文继续拒绝；严格协议和保守复核仍可能误拒绝正常措辞。
- 简单优缺点仍按原观点精确分组；未扩展多商品多维度二级归并，也未重构回答规划或整个前端。
- 历史公开接口不恢复自由解释；数据不足时的限制仍可更简洁。重点选择最多八项，复杂多组问题可能回退或需要详情。
