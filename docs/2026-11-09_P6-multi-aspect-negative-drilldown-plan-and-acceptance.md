## 2. 最小架构方案

### 2.1 模式与触发条件

新增服务端派生的 `analysis_mode='multi_aspect_negative_drilldown'`，底层仍使用 `analysis_type='aspect_drilldown'` 和现有 `get_aspect_drilldown`。不新增同名工具、LLM 规划器、API 必填参数或数据库表。这样可复用既有查询契约、单维度结果模型和统计/引用校验。

仅在以下条件全部满足时自动触发：同一会话、一个明确 SKU、上一轮为当前窗口的未限定维度负面排名、当前问题要求具体表现且未显式指定单一维度，商品/日期/数据集/标注身份与该排名一致。明确问数量、原文、正面或某个具体维度时，走相应已有路径。品牌多 SKU、多个无法唯一选择的历史排名、跨会话、缺少可信排名或范围已变更时，不拿旧排名自动下钻。

### 2.2 恢复可信排名与选择前三维度

1. `load_analysis_context` 重新验证历史任务后，提取 `ranking_basis`：来源任务/结果 ID、查询时刻、范围指纹、成功标注分母和六维负面去重评论数。存在任务级验收记录时也须通过；旧任务缺少该记录时，必须通过现有重新验证流程。失败轮次只贡献用户请求，不提供排名或数字。
2. 从完整六维统计中排除负面数为 0 的维度，以 `(-negative_review_count, aspect_key)` 排序，取最多三个；并列规则与 `get_top_issues` 一致。不足三个只分析实际非零维度；全为零则明确没有支持内容分析的证据，不编造主题。
3. 选择依据保存为服务端元数据，记录目标维度和选中原因。用户贴出的历史数字不成为可信排名输入。用户提供的记录对应客服、使用效果、物流，但本次没有生产查询来确认这些数字。
4. 继承上一轮商品、来源、数据集、标注身份、当前/基线窗口和截止时间，情感固定为经过确认的 `negative`。显式范围修改优先，但旧排名不能用于新范围；应先取得新范围的有效排名。显式单维度请求优先于自动前三维度。

### 2.3 读取、分类与结果组织

1. 先检查整轮工具预算，冻结三个不同的工具要求，每个都明确 SKU、维度和 `negative`。
2. 在同一个只读事务中读取上下文及三份观点/总体计数。复用上下文中的全维统计核对历史排名样本计数；如已变化，停止自动分类并提示刷新排名，不悄悄替换成新的前三名。计数一致不等于历史内容完全未变，报告分别记录排名快照与本轮读取时刻。
3. 三份输入先在现有查询缓存中冻结，再释放数据库事务，随后串行分类；避免等待模型时维持长数据库快照。P6 分类阶段只消费预读输入，缓存未命中应阻断，不重新开启另一份数据快照。
4. 每个维度独立运行 `review_topics` 的主题发现和归属复核，候选目录及观点互不混用。复用 `topic_id(name, aspect, sentiment)`，即使主题名称相同，也不跨维度合并。
5. 输出按上轮排名顺序分为三个维度，分别展示维度总体计数、候选具体问题、主题去重评论数、该维度纳入样本分母、覆盖率、未归类数和代表原文。每维度公开最多三个主题；完整受控结果仍保留在任务审计快照。
6. 复用模板与主题事实，不调用模型生成跨维度综合结论。摘要可以逐维列出已验证的候选问题，不能生成“共同根因”“统一投诉总数”等新命题。

### 2.4 统计与引用契约

- `D`：本轮该商品成功标注评论总数；`M_a`：维度 a 的全量负面去重评论数，一级维度占比为 `M_a / D`。
- `S_a`：本轮实际纳入该维度分类的去重评论数；`N_a,t = |set(review_ids of verified topic t)|`；主题占比为 `N_a,t / S_a`。主题观点数另由唯一观点 ID 计算。
- `S_a` 与 `M_a` 不一致时，明确显示非随机受限样本及覆盖率，不把样本主题数量写成该维度的全量频次，不外推。
- 同一评论可在多个维度或多个主题出现，各主题内去重；不把它们相加当作总体评论数，不按相同短句跨维度合并。
- 每个公开主题至少有一个实际支持观点，追溯链为结果 ID → 维度/主题 → 观点 ID → 评论 ID、标注/修订来源 → 原始引用及正文区间。引用须与原文逐字一致，不由模型生成数字、来源或偏移。
- 证据按维度公平分配，先选择公开主题的实际支持引用，每维度最多三条、整轮最多九条。不能先耗尽全局证据预算，导致第三维度无引用。截断或省略不得冒充完整的归属证据。
- RAG/Embedding 不参与本模式，检索结果不能替代精确计数。

## 3. 模型调用与耗时预算（拟实施值）

当前单维度负面路径：最多 80 种表达、每批 20 种，因此理论最多 `1 + ceil(80/20) = 5` 次主题调用，单维度预算 60 秒。简单复制三遍会变成最多 15 次主题调用、三份独立时间预算；回答解释还可能另外调用模型，不能作为 P6 的默认方案。

P6 首版采用明确的受限样本，不承诺全量主题分类：

| 项目 | 整轮上限与规则 |
| --- | --- |
| 目标维度 | 最多 3 个，按历史负面排名固定 |
| 分类样本 | 每维度最多 20 种不同表达、最多 200 条原始观点；保留现有最多 100 条评论的读取边界。按确定性顺序选择并报告排除/未覆盖情况 |
| 主题模型 | 每维度发现 1 次、归属复核 1 次，合计最多 6 次；无观点则 0 次。失败尝试计入预算，不自动重试或修复输出 |
| 规划/意图/回答模型 | 本模式均为 0 次，规则编译、确定性模板回答 |
| 请求输出 | 发现最多 1,200 tokens，归属最多 3,000 tokens；三维输出额度上限 `3 × (1200 + 3000) = 12,600 tokens` |
| 请求输入 | 每次 payload（含 schema）最多 16,000 UTF-8 字节；系统提示另计。超限在 SDK 前拒绝，不静默截断或追加批次 |
| 单请求时间 | `min(配置超时, 20秒, 本维度剩余时间, 整轮剩余时间)`；SDK 重试为 0 |
| 共享分类预算 | 每维度至多 40 秒；三维共享分类截止时间 120 秒，截止后不得再发请求。整个任务还含读取、校验和序列化耗时，不把 120 秒说成整任务耗时保证 |
| 工具预算 | 正常 3 维：现有上下文 1 次 + 主题工具 3 次，共 4 次；预读复用同一缓存，不重复工具或数据库提取。当前默认工具上限为 12，但仍检查实际配置 |
| 重试与扩充 | 不自动重试、追加样本、扩大维度或补查其他工具；失败维度可由用户明确发起新的单维度请求 |

样本过长、候选定义过大导致 payload 超限时，该维度明确报告输入预算不足，不能为满足六次上限而隐藏样本缺口。预计费用不能从字节数推算为 tokens 或人民币；本轮不查询供应商价格、不触发计费。将来真实调用需另行明确授权范围、供应商和本次限额。

预算对象必须由 P6 整轮创建并传给每个子分析，调用前原子预留额度、记录尝试和耗时；单维度旧路径保持原默认值。

## 4. 失败降级与任务级完整性

根结果保存 `analysis_mode`、`ranking_basis`、`required_aspects`、逐维度状态、预算用量和可发布结果 ID。未执行维度只记状态，不伪造成功工具结果。

| 情况 | 维度行为 | 整轮与公开内容 |
| --- | --- | --- |
| 三维均完成且有受支持主题 | 独立校验范围、归属、计数、引用 | 完整通过；按维度输出，`complete=true` 只表示受限样本的业务流程完整，不表示人工确认 |
| 单个维度超时/连接失败/响应不合法 | 该维度失败，保留阶段及原因；不发布其候选主题或频次 | 若其他维度独立完成，可显示这些已验证部分；整轮 `partial`、`complete=false` |
| 部分归属批次完成 | 该维度记 `partial`，不把尚未归类的整体样本当完整主题统计 | 已有该维度快照仅用于审计；其他完成维度可独立发布 |
| 无可支持主题、全未归类或无观点 | 明确证据不足、未归类/未处理数量，不编造主题 | 有其他完成维度则部分完成；全部不足则无可发布主题，明确业务目标未完成 |
| 工具预算不足 | 模型调用前停止，不静默只选一两个维度 | 保留原定目标，明确预算限制；不能验收为前三维度已完成 |
| 共享时间/调用额度耗尽 | 尚未开始的维度标 `skipped_budget` | 不追加请求；可发布独立完成部分，整轮仍未完成 |
| 供应商鉴权/额度错误 | 停止余下收费请求，保留受控错误码 | 不无意义地向后两个维度继续发请求 |
| 作用域、情感、排名依据或来源身份失配 | 全局硬失败 | 整轮不发布正常分析，不能当普通模型故障绕过 |

复用现有 `validate_report`、`validate_topic_result` 和单维度压缩/回答校验；每个可发布维度使用只包含该维度精确要求的子计划校验。父计划始终保存全部目标，不把失败维度从父计划删除来制造通过。

扩展 `review_acceptance` 独立检查：目标维度是否正好为验证排名的前三个非零项、是否每维都执行、是否同 SKU/数据集/日期/负面情感、是否完整分类并有来源证据。重复执行一个维度三次、缺少第三个维度、只有统计工具或无原文都不得通过。

部分发布使用独立子分析的已验证结果；父级标明“仅已发布部分的数字和引用通过”，并保留整轮 `task_acceptance.status=partial / complete=false`。不得将子集冒充完整计划传给现有整体压缩验收。旧模式的部分完成发布规则不改变；冻结运行时契约、评估文件、RAG 许可与审批资产不修改。

## 6. 测试矩阵与验收门槛

先使用临时 SQLite、合成评论、可控分类器与假时钟；网络、收费模型与 Embedding 均阻断。数据库原文保留真实位置/来源字段，不用模拟 API 替代核心查询链。测试中的数量属于合成样本。

| 场景 | 必须验证 |
| --- | --- |
| 用户原始两轮 | `100013588053` 六维差评排名 →“具体体现在哪里”；自动选择验证排名前三，而非要求单维度 |
| 常见省略表达 | “差评具体体现在哪里”“具体表现是什么”；继承负面方向和单商品 |
| 同会话刷新/任务链接恢复 | 保留排名来源和实际范围，仍可从服务端恢复并校验 |
| 明确指定物流 | 仅分析物流，不触发默认三维；改问数量/原文也使用相应路径 |
| 商品/日期/数据集/版本变更 | 旧排名失效，不能用旧计数选择新范围维度；同会话显式变更优先 |
| 跨会话/失败或伪造父任务 | 无法恢复另一会话或不可信结果，拒绝自动选择 |
| 排名并列、非零不足三项/全零 | 稳定排序，最多三项，不执行零维度，不编造主题 |
| 当前数据计数变化 | 分类前提示重查排名，不把当前输入和历史分母混用 |
| 三维工具覆盖 | 正好执行三个不同目标；删掉第三个、重复第一个、额外加维度均不能通过 |
