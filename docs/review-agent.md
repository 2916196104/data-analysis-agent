# 使用只读评论分析 Agent

评论 Agent 复用 HelloAgents 和现有评论统计函数，根据问题选择工具，返回统计、商品对比和原文证据。它使用已有标注；需要先准备评论数据和至少一个标注版本。

## 在工作台提问

1. 按原方式运行 `python run.py`，在工作台选择数据集、商品、分析时间和标注版本。
2. 点击“Agent 问答”，填写问题，或选择趋势、商品对比、包装证据的示例问题。
3. 点击“提交问题”。后端读取已有 `.env` 的模型配置，通过持久化任务队列执行。
4. 查看分析结论、对应结果表格、原文证据和工具执行记录。点击“查看原文”可以查看完整评论、观点、原文位置和人工/模型来源。
5. 刷新或从“任务记录”重新打开结果；恢复结果不会再次调用模型。“下载 Agent JSON”导出本次完整结果。

问题示例：

- 按日查看评论数量和负面评论数量的趋势。
- 对比所选商品的负面评论占比，并展示包装负面评论的原文证据。
- 查看六个维度的问题数量及较基线的变化。

商品和日期范围由页面绑定，首版不从问题中自动改写范围。需要其他范围时先调整页面选择。Agent 模型使用后端的 `LLM_MODEL_ID`、`LLM_BASE_URL` 和 `LLM_API_KEY`；“标注版本”决定查询哪一套已有观点，两者可以使用不同模型。

## 结果如何生成

模型负责选择工具、修正工具参数和返回结果 ID。代码核对实际结果引用，并把统计数字和原文片段整理成中文回答；首版不生成自由发挥的原因解释。

| 工具 | 能力 |
| --- | --- |
| `get_analysis_context` | 已选范围、商品 ID、标注覆盖率、维度和情感枚举；执行前自动读取一次 |
| `get_trend` | 当前窗口按 UTC 日/月统计整体评论趋势 |
| `compare_products` | 当前窗口的商品数量、覆盖率和负面占比对比 |
| `get_top_issues` | 六维度问题数量、占比和基线变化 |
| `get_evidence` | 按商品子集、维度、情感和当前/基线窗口分页查询原文证据 |

所有工具共用一条只读事务，读取同一数据库快照，并使用既有的去重、统计分母和最新人工复核规则。`as_of` 沿用现有业务口径，仅筛选评论发布时间，不表示重建历史时刻的人工复核状态。

空分母不转成 0。工作台把成功标注数直接列为“分母”，同时展示负面数/成功标注数和成功标注数/有效正文数；成功数为 0 时按“待标注”“标注失败”“无有效正文”或“无评论”说明原因。已有成功标注但负面数为 0 时仍显示真实的 `0.0%`。商品对比支持搜索和状态筛选，历史结果也会按表格重新排版，不再把所有商品拼成一段长文本。

“准备待处理商品”只打开现有标注表单，不会自动调用模型。入口会带入 Agent 结果的数据集、商品、UTC 日期和截止时间，用户明确提交后才创建标注任务；完成后需要用新标注版本重新分析。原文证据在页面中以引用卡片展示，完整文本、哈希和行号仍可从详情或 JSON 下载查看。

成功回答会附带确定性校验记录：计数关系、负面占比和覆盖率分母、原文引用位置，以及最终结果 ID 是否覆盖所有已完成查询。任一校验失败时任务不会标记为成功回答。

## 接口与任务兼容

继续使用 `POST /api/v1/tasks` 的 `kind="analysis"`，在已有分析参数中增加可选的 `question`。省略 `question` 仍执行原结构化分析，不调用问答模型，原任务载荷的幂等哈希保持不变。

提交 Agent 任务时必须明确 `source` 和 `dataset_version`，同时保留原有商品、日期、基线和标注身份字段。客户端不能传入 `model_identity`；服务端自动冻结执行模型和 `review-agent-v1` 提示词版本。执行前或重试时发现模型身份变化，会要求重新提交任务。

Agent 结果直接保存在任务的 `result` 中：

- `agent=true`：标识问答结果，前端不再请求 `/analysis-runs/{run_id}`。
- `status`：`ok`、`unsupported` 或 `error`。错误对应任务 `failed`；能力或范围不支持时正常保存说明。
- `scope`、`snapshot_at`：已校验的查询范围和查询开始时间。
- `answer`、`result_ids`、`results`：由实际工具结果整理的回答及结果引用。
- `validation`：代码生成的数字、分母、引用和结果覆盖校验；`status=passed` 才允许发布成功回答。
- `trace`、`usage`、`model_calls`、`tool_calls`：模型用量、工具记录和调用次数。
- `warnings`：分母、样本量及证据解释限制。

只读指业务库：Agent 不写评论、观点、人工复核、分析运行或告警表。任务队列仍保存提交状态和执行结果，无需新增数据库表或迁移。

## 首版边界与错误处理

- 模型服务须支持原生工具调用。现有 `AGENT_MAX_STEPS`、`AGENT_MAX_TOOL_CALLS`、`LLM_TIMEOUT_SECONDS` 和 `LLM_MAX_RETRIES` 继续生效；自动读取上下文也计入工具调用次数。
- 工具仅接受声明的参数；数据库路径、来源、版本和日期不能由工具调用改写，商品子集不能越出已选范围。
- 相同工具与相同规范化参数复用本次结果。最终 JSON 格式最多纠正一次，仍受原调用预算限制。
- 未解决的工具失败、虚构结果 ID、遗漏已完成结果和耗尽预算都不会宣称分析成功。
- 最多选择 100 款商品；趋势最多 366 天或 240 个月；证据默认每页 5 条，最多 10 条。需要更多证据时可在问题中要求查询其他页，但仍受调用预算限制。
- 首版是单轮只读问答，不自动标注、执行任意 SQL/代码或维护多轮会话。原“开始分析”入口继续执行固定分析与规则检查。

## 验证

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_review_agent.py -v
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

离线测试使用真实 HelloAgents/OpenAI SDK、脚本化 HTTP 模型响应及临时 SQLite 数据库。浏览器验收启动本机模拟模型和独立数据库，覆盖三类查询、原文详情、JSON 下载和刷新恢复。它验证接口与业务行为，不代表真实模型的理解准确率。
