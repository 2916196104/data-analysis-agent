# 证据补查闭环：最小实施设计

基于 3.5 补充验收继续实施，保留工作区已有未提交改动。既有诊断与评测报告作为本轮基线，不改写为本轮成果。

## 根因和切入点

`run_review_agent` 在原查询校验、压缩后直接生成回答，`assess_evidence` 尚无执行入口。Worker 已提供持久队列、幂等提交、进度和失败发布保护，因此补查作为同一个已领取任务的一次阶段执行，不创建循环子任务。

原结果通过统一校验后关闭原事务，再建立受限只读补查上下文；每条建议单独校验，预算从原任务剩余额度扣除。全部通过后重新校验合并结果、重新压缩和构建事实目录。任何查询、范围、引用或预算失败均禁止完整成功发布。补查需要澄清则给出具体问题，不猜测商品、情感或窗口。

日期子窗口只接受诊断中由唯一维度时间序列首末有效桶计算出的窗口，并重新核对原范围、桶边界和可比样本；其他需要确认的建议不执行。结果保存实际执行范围，历史读取和会话恢复也验证这些范围，不能信任仅有的持久化“通过”标签。

## 隐私与语义

自动 `get_aspect_drilldown` 会新增原文发送给外部主题模型。本轮自动补查固定转为同商品、同维度、同情感的既有 `get_opinion_breakdown`，明确记录转换原因；不改变用户显式选择的既有主题归并工具，也不把精确分组冒充语义聚类。

本地语义模块只识别有明确引文位置的有限表达：外箱状态/盒内固定/封口、明确自述商品完好、发货前等待/运输追踪/预约履约。每个关系绑定原事实、证据 ID、原文跨度、商品和日期；否定、模糊或不认识的表达不猜测。不会生成新主题计数、责任、真实性能或未来预测。

这些关系在模型返回之后由后端组装，原文和新语义衍生内容不进入外部回答模型。原有统计事实仍使用现有回答模型；模型失败时，本地可核验的内容归属和事实仍可保守回答，不伪装成模型生成。

## 涉及文件与验收

新增受控执行和本地语义模块；接入 `reviews.py`、回答组装及历史范围校验；只作必要的证据关系展示适配，不调整布局、数据库和标注系统。内部诊断新增补查执行记录和本地语义版本，既有 API 必填参数及指标不变。

以 P01、L02、T02 的自然语言问题通过真实 HTTP API、持久队列、真实 Worker、只读工具和最终公开读回验收；使用临时合成 SQLite 与已配置真实模型，记录实际调用、耗时和失败。另覆盖 partial/failed、日期越界、商品歧义、共享预算、引文异常、幂等和只读保护。不能将构造快照测试计为完整链路通过。本轮完成后停止。
