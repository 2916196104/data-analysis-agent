## RB03 子问题的静态审阅

原题要求在指定保存评论范围内找到买家明确自述送货慢并引用原文；配送、安装对象需分开，不推断总体时效。[target 与 fact](E:/AllProject/data-analysis-agent/src/data_analysis_agent/agents/review_reported_facts.py:41) 的静态规则允许以下至多两种候选组件问法，且其事实都映射到 `delivery_slow`：

1. **“有没有送货很慢的反馈？”** 其中“送货很慢”符合现有有限事实词形，但“很慢”比原题的“慢”更窄；不能保证覆盖原题的全部表达。
2. **“有没有配送慢的反馈？”** “配送慢”符合词表；是否与原题“送货慢”在本次业务语境下完全等价，仍需独立人工审阅，不能仅凭程序把两者映射到同一 ID 即视为证明。

这两种表达都不包括人工标签、引用坐标或候选结论；但都不能单独携带原题的保存池身份、商品日期约束、原文引用要求或不扩大全商品的限制。这些条件必须由独立冻结的输入契约及完整执行链保留。当前没有经独立批准的等价表达，不能修改 P2-B1 的 `component_subquery=null` 或允许它进入真实判断器。上述匹配只依据源码静态阅读，**没有调用 `target` 或 `assess`**。

新增 [p2b2_synthetic_workflow.py](E:/AllProject/data-analysis-agent/scripts/p2b2_synthetic_workflow.py) 与 [测试](E:/AllProject/data-analysis-agent/tests/test_p2b2_synthetic_workflow.py)：

2. 合成输出 Schema 严格限定 `synthetic` / `SYNTHETIC_EXAMPLE`，显式区分 `direct_support`、`unsupported`、`unknown`、`insufficient_evidence`、`explicit_opposite`、`execution_failure`、`not_executed`，另区分 `refusal`。现有 Runtime 自身仅有其既定输出状态；不得把合成 Schema 声称为 Runtime 已实现全部类别。
3. 合成封存仅允许系统临时目录中新建专用目录、独占创建预测和收据，返回 SHA-256 供外部保管；同名目标存在即停止。评分接口仅读取合成封存并核对独立传入摘要及收据，再接收合成参考；不写预测，也不读 Gold。篡改预测后即使重写收据，旧外部摘要仍会阻断。
4. unknown、拒答、执行失败和未执行不会记为正确事实判断。零发布断言时 Unsupported Claim Rate 为 N/A；零引用时 Citation Precision 为 N/A；原题和 RB09 无法比较的条件仍为 N/A。

这些是**临时目录中的合成流程演练**。文件独占创建和返回摘要不提供操作系统不可变封存，也不能保证持有同一账户权限的人无法修改预测及自报新摘要；实际流程需要隔离的独立摘要保管者、不可变或可验证的封存机制以及受限评分身份。当前合成评分接口不接受真实 RB03 或 Gold，也没有生产评分器可执行入口。因此“合成封存与只读评分可用”不等于“真实预测已具备不可变封存和评分准入”。
